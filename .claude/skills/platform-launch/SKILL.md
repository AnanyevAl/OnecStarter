# Запуск 1С:Предприятие и выбор версии платформы

Полные таблицы ключей командной строки, строки соединения и `1cestart.cfg` — `reference.md`
в этом каталоге.

## Раскладка

Клиенты — в `<InstalledLocation>\<полная версия>\bin\`:
`1cv8.exe` (толстый клиент и Конфигуратор), `1cv8c.exe` (тонкий), `1cv8s.exe` (тонкий файловый).

**[Ф]** Для файловой базы стартер запускает **`1cv8c.exe`**, а не `1cv8s.exe`, — и при
`App=Auto`, и при явном `App=ThinClient` (проверено 31.07.2026, снят `ExecutablePath`).
Единственный снятый случай запуска `1cv8s.exe` — клик «1С:Предприятие» по секции-группе:
максимальная установленная версия с пустой строкой соединения.

**[Ф]** `/AppAutoCheckMode` стартер передаёт клиенту только при `App=Auto`; при явном
`App=ThinClient` командная строка собирается без него (`ENTERPRISE /IBName"..."
/AppAutoCheckVersion`).

Штатный стартер — `<InstalledLocation>\common\1cestart.exe`, **вне каталога версий**.

## Факты, на которых ошибаются

### 1. Разрядность задаётся ключом `/AppArch`, а не деревом установки

Значения: `x86`, `x86_prt` (по умолчанию), `x86_64`, `x86_64_prt`.
Те же значения — у ключа `AppArch` в `.v8i`.

Утверждение «x86 ставится в `Program Files (x86)`, x64 — в `Program Files`, разрядность выбирается
выбором дерева» — ложное. Каталога `Program Files (x86)\1cv8` может не существовать вовсе.

### 2. Источник истины об установленных версиях — файловая система

Реестровых ключей `HKLM\SOFTWARE\1C\1Cv8` и `...\WOW6432Node\1C\1Cv8` может не быть.

Порядок: `InstalledLocation` из конфигурационных файлов → перебор подкаталогов →
**проверка наличия `bin\1cv8.exe`**. Имя каталога само по себе версию не подтверждает.

### 3. `DefaultVersion` уточняет неполную `Version`, но проигрывает точной

Оба — штатные ключи `.v8i`. ИТС утверждает, что используется именно `DefaultVersion`,
а не `Version`. **[Ф] Опровергнуто экспериментом 31.07.2026** (снят `ExecutablePath`
реального процесса, платформа 8.3.25):

| `Version` | `DefaultVersion` | Что запустилось |
| --- | --- | --- |
| `8.3.25.1560` (точная) | `8.3.25.1633` | `8.3.25.1560` |
| `8.3.25` (маска) | `8.3.25.1560` | `8.3.25.1560` |

`DefaultVersion` — не «что реально запускалось в прошлый раз»: при `Version=8.3.99.1`
запустилась `8.3.27.2214`, а записано `DefaultVersion=8.3.99.1` (**запрошенное**).

**[Ф] 05.08.2026 (T-05.5): «уточняет маску» — слишком слабо, сопоставления с маской
нет вовсе.** `DefaultVersion` побеждает неполную `Version`, даже когда ей не соответствует;
заданный, но не установленный `DefaultVersion` даёт тихий фолбэк на максимум вообще —
к максимуму с префиксом маски платформа не возвращается:

| `Version` | `DefaultVersion` | Что запустилось |
| --- | --- | --- |
| `8.3.25` (маска) | `8.3.22.1923` — установлен, **вне маски** | `8.3.22.1923` |
| `8.3.25` (маска) | `8.3.25.9999` — в маске, **не установлен** | `8.3.27.2214` — максимум вообще |

### 4. `DefaultVersion` в `1cestart.cfg` — таблица подстановки, а не скаляр

Грамматика: `<маска>[-<полная версия>][;<разрядность>]`. Строк может быть несколько.

```ini
DefaultVersion=8.3-8.3.24.100      ; база просит 8.3    → запустить 8.3.24.100
DefaultVersion=8.2.15-8.2.15.315   ; база просит 8.2.15 → запустить 8.2.15.315
DefaultVersion=8.3;x86_64_prt      ; любая база → клиент 8.3, преимущественно 64 бита
```

Разделитель — **дефис**, не второй знак равенства.

### 5. Сравнение версий — покомпонентное числовое

Лексикографически `8.3.9` > `8.3.18` > `8.3.10`. Числовой порядок обратный.
Сравнение префикса — по кортежам чисел, не `startswith`: маска `8.3.25` не должна ловить `8.3.250.1`.
Маску нельзя дополнять нулями — иначе она перестаёт быть маской.

> **[Ф] Маска разрешается в максимальную установленную С ЭТИМ ПРЕФИКСОМ.** Эксперимент
> 31.07.2026: `Version=8.3.25` при установленных `8.3.10.2252`, `8.3.18.1334`, `8.3.20.2290`,
> `8.3.22.1923`, `8.3.25.1560`, `8.3.25.1633`, `8.3.27.2214` → запустилась **`8.3.25.1633`**.
> Формулировка ИТС «максимальный номер установленной версии» без оговорки про префикс
> буквального прочтения не выдержала. Маска в файле при этом не разворачивается в полную версию.
>
> Разница меняет поведение продукта. Реализовывать через явный флаг с логированием источника
> решения, значение по умолчанию выбрать **только после эксперимента** — см. «Непроверенное»
> в `reference.md`.

### 6. `WA=1` в `.v8i` не равно `/WA+`

`WA=1` — «пытаться аутентификацию ОС, при неудаче спросить логин/пароль».
`/WA+` — «обязательная аутентификация ОС». Прямое отображение меняет поведение.

**[Ф] 31.07.2026: транслировать `WA` в командную строку не нужно** — при запуске по имени базы
штатный стартер ключи `/WA` вообще не передаёт (снято дважды):

```
1cv8c.exe ENTERPRISE /IBName"empty" /AppAutoCheckVersion /AppAutoCheckMode
```

Поведение «попытаться ОС-аутентификацию, при неудаче спросить» платформа отрабатывает сама,
читая `WA=1` из `.v8i` по `/IBName`. Открытым вопрос остаётся только для запуска по строке
соединения (`/F`, `/S`), где `.v8i` не участвует.

**[Ф] 31.07.2026, запуск по `/F`:** на базе, где у пользователей ИБ ОС-аутентификация
не настроена, `/WA+`, `/WA-` и запуск без ключа дают **одинаковый** диалог логина —
`/WA+` не падает с ошибкой при недоступной ОС-аутентификации. Кейс с реально настроенным
сопоставлением пользователей ОС не проверен.

### 7. [Ф] Несуществующая версия — тихий фолбэк на максимум вообще

`Version=8.3.99.1` при `AppAutoInstallLastVersion=0`: штатный стартер **без единого
предупреждения** запустил `8.3.27.2214` — максимальную установленную. Пользователь узнаёт
о расхождении версии только по поведению базы. Наш продукт обязан показывать это до запуска.

### 8. [Ф] Имя в `/IBName` сопоставляется без учёта регистра, дубли пресекает клиент

05.08.2026 (T-05.3):

- две секции с одним именем → сообщение **«Не уникальное имя информационной
  базы "…"»**, запуск прекращён — в том числе когда имена различаются **только
  регистром** (`[T05-Дубль]` + `[t05-дубль]`);
- запрос `/IBName"t05-дубль"` находит единственную секцию `[T05-Дубль]` —
  поиск регистронезависимый;
- **ненайденное имя — не ошибка**: клиент молча открывает окно выбора
  информационных баз. Диагностику «имя не найдено» вызывающий делает сам.

### 9. [Ф] `/IBConnectionString` — значение прижато к ключу, кавычки удвоены

05.08.2026 (T-05.1): `/IBConnectionString"File=""D:\db\empty"";"` — форма симметрична
снятой форме `/IBName`. Путь с пробелом внутри удвоенных кавычек работает.
Запуск по строке соединения `ibases.v8i` не меняет.

### 10. [Ф] `/IBName` видит общие списки, и клиент материализует запись

05.08.2026 (T-05.2): клиент `1cv8c.exe`, запущенный по `/IBName` с именем из
`CommonInfoBases`, находит базу и **дописывает её секцию в пользовательский
`ibases.v8i`** — тот же `ID`, дописаны `App=Auto`, `WA=1`, `External=1`;
`Version` не копируется. Дубль «пользовательская + общая» — штатное состояние
после первого запуска общей базы; слияние — по `ID`.

### 11. [Ф] Окно списка баз рисует не `1cestart.exe`

05.08.2026: `1cestart.exe` без аргументов мгновенно завершается, делегируя окно
процессу `1cv8s.exe` **максимальной установленной версии** с пустой строкой
соединения (`"" /AppAutoCheckVersion /AppAutoInstallLastVersion-`). Это же
объясняет двухпроцессный след T-02.9.

### 12. [Ф] Путь к списку баз платформа берёт не из переменной `APPDATA`

09.08.2026. Процесс, запущенный с подменённой переменной окружения `APPDATA`,
передаёт её потомкам, но платформа её **игнорирует** и читает список из
настоящего профиля пользователя — судя по всему, через shell API
(`SHGetKnownFolderPath`); **[Д]** проверен результат, не механизм.

Снято дважды, разными путями:

- `1cestart.exe`, запущенный с `APPDATA` на каталог-песочницу, переписал
  **живой** `%APPDATA%\1C\1CEStart\ibases.v8i`, а копию в песочнице
  не тронул вовсе (хеш копии не изменился);
- клиент `1cv8c.exe`, запущенный нашим кодом по `/IBName` с именем, которое
  существует **только** в песочнице, имени не нашёл и открыл окно выбора базы
  («Запуск 1С:Предприятия») — то есть искал в живом списке. Реакция на
  ненайденное имя совпадает с фактом 10 источника T-05.2.

**Следствие для экспериментов:** подмена `APPDATA` изолирует программу
на Python (она читает `os.environ`), но **не изолирует ни один процесс 1С**.
Песочница из копии списка годится для проверки своего кода и бесполезна
для всего, что запускает платформу: та всё равно пойдёт в живой файл.

### 13. [Ф] Запуск по `/IBName` открывает живой `ibases.v8i` на запись

09.08.2026, тем же опытом. После запуска клиента по `/IBName` у живого
`ibases.v8i` **сменился `mtime`, а содержимое осталось прежним** — размер
и SHA-256 совпали до последнего байта, при том что запрошенное имя в этом
файле отсутствовало и база не открылась вовсе.

Уточняет факт T-02.5 «CLI-запуск файл не трогает»: **содержимое** не трогает,
но файл открывает. Для сверок «менялся ли список» это значит, что `mtime`
и время последней записи — ненадёжный признак, сверять надо содержимое
(хеш или разбор), иначе штатный запуск базы читается как правка файла.

## Алгоритм подбора версии

`/AppAutoCheckVersion` (по умолчанию включён). По ИТС:

1. Версия базы определяется по `Version` в `.v8i` — для файлового варианта,
   либо **по ответу сервера** — для клиент-серверного.
2. **Номер полный** → поиск по `InstalledLocation`. Нет → поиск дистрибутива по
   `DistributiveLocation`, установка. Нет и там → запуск прекращается с ошибкой.
   **[Ф]** При `AppAutoInstallLastVersion=0` и отсутствии версии стартер молча берёт
   максимальную установленную вообще (см. факт 7), а не прекращает запуск.
3. **Номер неполный** → `DefaultVersion` секции базы **[Ф]** (применяется, даже если
   маске не соответствует — T-05.5), затем подстановка через `DefaultVersion`
   конфигурационных файлов, затем **[Ф]** максимальная установленная с этим префиксом.
   **[Ф]** Заданный, но не установленный `DefaultVersion` секции даёт тихий максимум
   установленных **вообще** — к максимуму с префиксом платформа не возвращается.

`/AppAutoCheckMode` — про **клиента**, не про версию: определяет режим запуска базы и пользователя
и при несоответствии перезапускает нужного клиента **той же версии**.
`/RunModeManagedApplication` отключает автоподбор клиента.

### Если версия разрешается своим кодом

Передавать `/AppAutoCheckVersion-`. Иначе платформа переиграет выбор по своему алгоритму,
а при включённом `AppAutoInstallLastVersion` ещё и полезет ставить дистрибутив: UI покажет одно,
запустится другое.

**[Ф] 05.08.2026 (T-05.4), снято экспериментально в обе стороны:** exe `8.3.25.1633`
при `Version=8.3.22.1923` в секции с `/AppAutoCheckVersion-` продолжил работать сам —
версия удержана; с `/AppAutoCheckVersion` наш процесс завершился, и платформа
перезапустила клиента `8.3.22.1923` (`ENTERPRISE /IBName"..." /AppAutoCheckMode
/AppAutoCheckVersion` — ключ `/AppAutoCheckMode` она добавила сама).

`/AppAutoCheckMode` при этом оставлять включённым — подбор клиента зависит от прав конкретного
пользователя в базе, снаружи это не воспроизвести.

## Пароль в командной строке — неустранимая утечка

`/P<пароль>` и `Pwd=` строки соединения попадают в argv и читаются любым процессом
пользователя через `Win32_Process.CommandLine`. У GUI-клиента 1С нет аутентификации через stdin.

Хранить только в Windows Credential Manager (DPAPI), функцию держать выключенной по умолчанию,
пользователя предупреждать явно. Обойти нельзя — можно только ограничить хранение.

## Конфигурационные файлы

Три уровня: общий `1cescmn.cfg`, локальный для всех пользователей и локальный `1cestart.cfg`.
`1cestart.cfg` — **UTF-16LE**, в отличие от `.v8i` (UTF-8).

Приоритеты **различаются по параметрам** — три разных порядка, часть параметров объединяется
из всех файлов. Наивный merge словарей неверен. Таблица — в `reference.md`.
