# Формат .v8i — список информационных баз 1С

Файл описаний зарегистрированных информационных баз 1С:Предприятие.
Windows: `%APPDATA%\1C\1CEStart\ibases.v8i`. Linux/macOS: `~/.1C/1cestart`.

Полный перечень ключей с семантикой — `reference.md` в этом каталоге.

## Шесть фактов, на которых ошибаются

Каждый проверен на реальном файле или взят из ИТС. Интуиция даёт противоположный ответ.

### 1. Кодировка — UTF-8, BOM бывает и так и так

Соседний `1cestart.cfg` в том же каталоге — **UTF-16LE с BOM**. Два разных формата рядом.

**[Ф]** Платформа 8.3.25.1633 при массовой перезаписи `ibases.v8i` **добавила BOM UTF-8**
файлу, который до этого был без BOM (замерено 31.07.2026). Значит, в природе встречаются оба
варианта, и наличие BOM не признак «чужого» файла.

Определять по BOM, не хардкодить. Писать в той же кодировке, в которой прочитали.
Утверждение «BOM обязателен, иначе платформа не прочитает кириллицу» — ложное.

### 2. Секции без `Connect` — это группы дерева, а не базы

Документация помечает `Connect` обязательным и о группах не упоминает. На практике они есть:

```ini
[Клиенты]              ; ГРУППА — нет Connect, OrderInList=-1
ID=11111111-1111-1111-1111-111111111111
OrderInList=-1
Folder=/
OrderInTree=16640
External=0
```

Признак группы — **отсутствие `Connect` или пустое его значение**. Разбор, считающий каждую
секцию базой, даёт фантомные базы без строки соединения.

**[Ф] 05.08.2026 (T-05.6):** `Connect=` с пустым значением стартер показывает **группой**,
а первая же полная перезапись довершает превращение необратимо: ключ `Connect=` удаляется,
`Version` вычищается, дописываются групповые `OrderInList=-1`, `Folder=/`, `OrderInTree`,
`External=0`.

Из этого следует: **пустые группы представимы**, `Folder` — не единственный источник дерева.
Придумывать sidecar-файл для хранения групп не нужно.

**[Ф]** У секции-группы `Folder` — путь **родителя**, собственный путь группы = `Folder` + `/` +
имя секции. Подтверждено на реальном файле с вложенностью и экспериментом 31.07.2026: мастер
стартера («Добавить…» → «Создание новой группы») создал группу в корне (`Folder=/`) и подгруппу
в ней (`Folder=/<имя родителя>`) — вложенные группы поддерживаются штатно. Секция группы
дописывается в конец файла сразу по завершении мастера; состав ключей: `ID`, `OrderInList=-1`,
`Folder`, `OrderInTree`, `External=0`.

**[Ф] 05.08.2026 (T-05.8):** группа, записанная **без `OrderInTree`** (состав: `ID`,
`OrderInList=-1`, `Folder`, `External=0`), стартером видна и безвредна — `OrderInTree`
платформа дописывает сама при следующей полной перезаписи.

**[Ф] 05.08.2026 (T-05.7):** сопоставление `Folder` с именем группы — **регистрозависимое**,
в противоположность регистронезависимым именам баз (T-05.3). `Folder=/t05-группа` при группе
`[T05-Группа]` даёт **отдельный неявный узел** в дереве: стартер рисует группу из несовпавшего
пути, **секцию для неё не создаёт** и регистр `Folder` при перезаписях не нормализует. База
с «висячим» `Folder` — не сирота и не падает в корень.

**[Ф] 05.08.2026 (T-05.9):** удаление группы в стартере — **молчаливый каскад**: подтверждение —
единственный вопрос «Удалить группу "имя"?» без упоминания содержимого (одинаковый для пустой
и непустой группы), по «Да» удаляются секции и группы, и всей её вложенности. Не подъём
к родителю и не запрет.

### 3. `DefaultVersion` проигрывает точной `Version` — вопреки ИТС

Оба — штатные ключи секции. Не «ручная правка», не параметр только `1cestart.cfg`.

ИТС утверждает: «При последующих запусках будет использоваться именно эта версия
[`DefaultVersion`], а не та, которая указана в параметре `Version`». **[Ф] Опровергнуто
экспериментом 31.07.2026** (платформа 8.3.25, снят `ExecutablePath` реального процесса):

| `Version` | `DefaultVersion` | Что запустилось |
| --- | --- | --- |
| `8.3.25.1560` (точная) | `8.3.25.1633` | `8.3.25.1560` — победила `Version` |
| `8.3.25` (маска) | `8.3.25.1560` | `8.3.25.1560` — победил `DefaultVersion` |

Фактическое правило: **`DefaultVersion` уточняет неполную `Version`, но не переопределяет
точную**. Полный порядок разрешения — скил `platform-launch`.

**[Ф]** `DefaultVersion` — не «версия, реально использованная при последнем запуске»: при
`Version=8.3.99.1` (несуществующая) платформа запустила `8.3.27.2214`, а записала
`DefaultVersion=8.3.99.1` — то есть **запрошенную**, а не фактическую.

Та же пара для клиента: `App` (задано) и `DefaultApp` (определено автоматически).

Не проверено: `DefaultVersion`, не соответствующий маске `Version` (`8.3.25` + `8.3.22.1923`).

### 4. `Version` может быть неполной

Встречается `Version=8.3.25` при установленных `8.3.25.1560` и `8.3.25.1633`.
Сравнение строк на равенство сломается. Разрешение маски — см. скил `platform-launch`.

### 5. `OrderInList` — дробное число, не индекс

Реальные значения: `60.6814814814813`, `20.2271604938271`, `-1`, `311296`.
Разнородны по масштабу. Значим только относительный порядок.

**Не пересчитывать в плотную нумерацию** — это переписывает весь файл и ломает round-trip.

**[Ф] Платформа усекает `OrderInList` до 15 значащих цифр.** Замер 09.08.2026
на рабочем списке (64 секции, 17 из них с дробным `OrderInList`): после перезаписи
платформой дробных осталось 17, округлённых в целые — ноль, то есть **дробное
значение перезапись переживает**. Переписаны ровно два значения, и оба имели
16 значащих цифр: `0.7223985890652509` → `0.722398589065251`,
`5.056790123456771` → `5.05679012345677`. Все значения в пределах 15 цифр
уцелели побайтно.

Практика: писать `f"{value:.15g}"`. Шире — платформа молча нормализует,
и записанное не совпадёт с прочитанным при следующем чтении.

Там же снято, что перезапись делает с остальным файлом: ни одна секция и ни один
ключ не потеряны, `Connect`, `ID`, `Folder`, `Version` не изменились ни у одной
записи; меняются `OrderInList`/`OrderInTree` и порядок секций в файле; кодировка
и BOM сохраняются.

### 6. Пробелы вокруг `=` ломают ключ, и платформа добивает секцию

Имя ключа сравнивается платформой байт-в-байт, без трима. **[Ф]** Эксперимент 31.07.2026
с `Connect = File="...";` (пробелы вокруг `=`):

1. Ключ `Connect␣` не распознан → секция без валидного `Connect` → стартер показывает
   базу **как группу**. Запуск такой «группы» стартует клиент максимальной установленной
   версии с пустой строкой соединения — `Version` секции игнорируется.
2. При следующей перезаписи платформа сохранила строку с пробелами как посторонний ключ,
   но **удалила** из секции базовые ключи `App`, `WA`, `Version`, `AppArch` — как
   не относящиеся к группе. Порча необратима.

Наш разбор обязан вести себя так же: разделять по первому `=` без трима имени ключа.
«Починить» пробелы за пользователя = скрыть от него порчу, которую платформа всё равно
довершит.

## Round-trip обязателен

Задокументировано 30+ ключей, платформа пишет их выборочно и добавляет новые в новых версиях.

- неизвестные ключи возвращаются на место при записи;
- порядок секций и ключей внутри секции сохраняется;
- кодировка и стиль переводов строк сохраняются;
- модель = типизированные поля + `extra: dict[str, str]`.

Проверка: `serialize(parse(x)) == x` побайтово на реальных файлах.

## Разбор

`ID` — ключ идентичности и слияния. `Connect` им не является: допустимы несколько секций с
одинаковой строкой соединения и разными именами — так одну базу запускают в разных режимах.

**[Ф] 05.08.2026:** `External` — происхождение записи: `0` у локальных, `1` у секций,
которые клиент **материализовал из общего списка** (`CommonInfoBases`) при первом
запуске по `/IBName`. Материализованная секция несёт тот же `ID`, что и в общем
списке (дописаны `App=Auto`, `WA=1`; `Version` не копируется) — поэтому дубль
«пользовательская + общая» после первого запуска штатен, а слияние списков идёт по `ID`.

**[Ф] 05.08.2026 (T-05.3):** платформа считает **дублями имена, различающиеся только
регистром** — запуск по `/IBName` прекращается с «Не уникальное имя информационной
базы», а поиск имени регистронезависим. Проверка уникальности имён в своём коде
обязана сравнивать без учёта регистра.

Строку соединения **не разбирать как INI** — это отдельный формат `Ключ=Значение;` со своими
правилами кавычек. Разделять `Ключ=Значение` только по первому `=`.

Имя секции = отображаемое имя базы, отдельного ключа для имени нет.

## Запись

Файл параллельно правит штатный `1cestart.exe` и перезаписывает целиком. Поэтому:
временный файл в том же каталоге + `os.replace`, проверка `mtime`/хеша перед записью,
слияние по `ID` при внешнем изменении.

**[Ф] 31.07.2026 (платформа 8.3.25.1633):**

- **Файл не блокируется.** Ни при открытом окне `1cestart.exe`, ни при работающем клиенте
  открытие на запись и атомарная замена (`tempfile` + `Path.replace`) проходят успешно.
  Ретраи по `PermissionError` — на всякий случай, не по факту.
- **Перезапись платформы каноникализирует весь файл**, а не только затронутую секцию:
  `AppArch` переносится в конец секции, `OrderInList=-1` заменяется материализованными
  значениями (196608…1081344) со смещением секций в конец файла, `OrderInTree`
  пересчитывается, всем секциям разом дописывается `DisableLocalSpeechToText=0`,
  пустые строки-разделители между секциями удаляются (**[Ф]** 05.08.2026).
  **Опираться на порядок секций и ключей между сеансами нельзя — слияние только по `ID`.**
- Наши правки, сделанные сторонним процессом, платформа при этом сохранила
  (изменённое значение `Version` пережило перезапись).
- **Посторонний ключ переживает перезапись:** вписанный для эксперимента `XTest=1`
  после канонической перезаписи остался в секции (перенесён в конец). Неизвестные
  ключи платформа не удаляет — кроме случая, когда секция сменила вид (см. факт 6:
  у «ставшей группой» базы вычищаются базовые ключи).
- **События записи файла стартером:** полная перезапись — при запуске базы из окна
  стартера; дозапись секции — при создании группы мастером. CLI-запуск
  `1cestart.exe ENTERPRISE /IBName"..."` (даже с полным циклом сессии), открытие
  и закрытие окна стартера файл **не** меняют. `DefaultVersion` дописывается
  не при каждом запуске: для маски `Version=8.3.25` не записан, для несуществующей
  `8.3.99.1` — записан.
  **[Ф] 05.08.2026 (T-05.2):** прямой запуск клиента `1cv8c.exe` тоже умеет переписывать
  файл — запуск по `/IBName` имени из общего списка материализует секцию (`External=1`)
  **полной канонической перезаписью**. Полный цикл прямого запуска по `/IBName` базы
  пользовательского списка и запуск по `/IBConnectionString` файл не меняют.
