# Как устроены исходники

Документ для тех, кто читает или меняет код. Пользовательское — установка,
диагностика, сборка — в [README](README.md).

## Окружение

```powershell
uv sync              # создать .venv и поставить зависимости
uv run pytest        # тесты
uv run ruff check .  # линт
uv run mypy          # типы
```

`mypy` в режиме `strict` для всего, кроме `onecstarter.ui.*`.

## Структура

```text
docs/            требования, бэклог, спеки и планы, материалы разбора форматов
build/           spec-файл PyInstaller, сборочный сценарий, smoke собранного exe
src/onecstarter/
  domain/        модели предметной области — чистый Python, без Qt и ФС
  config/        чтение и запись форматов 1С (.v8i, 1cestart.cfg) без потерь
  platform_1c/   обнаружение версий платформы, выбор версии, командная строка
  security/      знание о секретах: что нельзя писать в логи и сообщения
  services/      оркестрация: загрузка, слияние источников, правки, запуск
  ui/            единственный слой, знающий про Qt
tests/           unit / integration / ui, фикстуры
.claude/skills/  доменные скилы: проверенные факты о форматах 1С и запуске
```

Ядро (`domain`, `config`, `platform_1c`, `security`, `services`) не импортирует
Qt — это проверяется тестом (`tests/unit/test_no_qt_in_core.py`). Так логика
выбора версии платформы — самое опасное место проекта — покрывается тестами
без запуска GUI.

## Правила для изменений

- Полный свод — [CLAUDE.md](CLAUDE.md): архитектурные инварианты, требования
  к фикстурам, процесс.
- Факты о форматах 1С и механике запуска — только из
  [.claude/skills/](.claude/skills/) или с пометкой об уровне достоверности;
  представления «по памяти» туда не попадают.
- В `tests/fixtures/` — только обезличенные файлы: реальные пути к базам
  и имена организаций в репозиторий не попадают.

## Сборка

См. [README, «Сборка из исходников»](README.md#сборка-из-исходников).
Сборка считается успешной после smoke-теста собранного экземпляра,
а не по факту упаковки.
