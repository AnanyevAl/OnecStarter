# Материал: формат `.v8i`

> Входные данные для скила `v8i-format`. Задача `T-01.1`.
>
> Метки достоверности: **[Д]** — официальная документация ИТС, «Приложение 3. Описание и
> расположение служебных файлов», версии 8.3.18…8.5.4 (набор ключей во всех версиях идентичен);
> **[Ф]** — измерено на машине разработчика 30.07.2026; **[?]** — не проверено.

## Общее

**[Д]** Файл описаний зарегистрированных информационных баз. Используют все клиенты.
Имя по умолчанию — `ibases.v8i`.

**[Д]** Расположение:

| ОС | Путь |
| --- | --- |
| Windows | `%APPDATA%\1C\1CEStart\` |
| Linux | `~/.1C/1cestart` |
| macOS | `~/.1C/1cestart` |

**[Д]** Текстовый документ в кодировке **UTF-8**, состоит из секций. Каждая секция описывает одну
информационную базу. Наименование секции в квадратных скобках, параметры — по одному на строку,
`Ключ=Значение`.

**[Ф]** Рабочий файл: 610 строк, 59 секций, **без BOM** (первые байты `5B 69 6E 74` = `[int`).
Пустых строк и комментариев нет.

> Сравнение: `1cestart.cfg` в том же каталоге — **UTF-16LE с BOM** (`FF FE`).
> Два разных формата рядом. Кодировку определять по BOM, не хардкодить.

## Полный набор ключей секции

**[Д]** Шаблон секции из документации — идентичен в 8.3.18 … 8.5.4:

```ini
[Наименование секции]
Connect=            ID=                  OrderInList=         Folder=
OrderInTree=        External=            ClientConnectionSpeed=
App=                AppArch=             DefaultApp=
WA=                 WSA=
Version=            DefaultVersion=      AdditionalParameters=
WebCommonInfoBaseURL=
HttpsCA=            HttpsCert=           HttpsCAFile=         HttpsCertFile=
HttpsCertSelect=
ShowInList=         MobilePublicKey=     WebCommonInfoBases=  InternetService=
UseProxy=           PSrv=                PPort=               PUser=          PPasswd=
StartupErrorHelpURL=                     StartupErrorHelpText=
```

### Обязательные

| Ключ | Смысл | Значения |
| --- | --- | --- |
| Наименование секции | Совпадает с наименованием информационной базы. В квадратных скобках | **[Д]** обязательный |
| `Connect` | Строка соединения. Разбор — см. `platform-launch.md` | **[Д]** обязательный |
| `ID` | Внутренний идентификатор. Формируется автоматически, **уникален в рамках одного файла**. Ручное формирование не рекомендуется | UUID |

**[Д]** Может существовать **несколько секций с одинаковой строкой соединения, но разными
наименованиями** — так одну базу запускают в разных режимах, не меняя её свойств.

> Следствие: `Connect` не является ключом идентичности. Ключ слияния — **только `ID`**.

### Дерево и порядок

| Ключ | Смысл |
| --- | --- |
| `Folder` | Наименование папки в дереве. **[Д]** Если не указан или опущен — база в корне списка. **[Ф]** Значения вида `/`, `/ClientGroup`, `/ClientGroup/Demo`, разделитель `/` |
| `OrderInList` | **[Д]** Порядок при представлении списком. Число. **[Ф]** Дробное (`60.6814814814813`), встречаются `-1` и крупные целые (`311296`) |
| `OrderInTree` | **[Д]** Порядок в ветви при представлении деревом. **[Ф]** `768`, `1024`, `16640`, `17408` |
| `External` | **[Ф]** Всегда `0` в наблюдаемом файле. Признак записи, полученной из внешнего источника |

> `OrderInList` — **дробное**, а не индекс. Никакой целочисленной арифметики.
> Значения разнородны по масштабу — сортировка есть, плотной нумерации нет.

### Клиент и версия

| Ключ | Значения | Смысл |
| --- | --- | --- |
| `App` | `Auto`, `ThinClient`, `ThickClient`, `WebClient` | **[Д]** Тип клиентского приложения. Редактируется в окне свойств базы |
| `DefaultApp` | `ThinClient`, `ThickClient` | **[Д]** Тип клиента, **определённый автоматически** и записанный программой запуска при `/AppAutoCheckMode` |
| `AppArch` | `x86`, `x86_prt`, `x86_64`, `x86_64_prt` | **[Д]** Разрядность клиента. Значения совпадают с ключом `/AppArch` |
| `Version` | Полный или неполный номер | **[Д]** Версия, которая **должна** использоваться. Редактируется в окне свойств |
| `DefaultVersion` | Полный номер | **[Д]** Версия, которая **реально использовалась при последнем запуске**. Записывается программой запуска при `/AppAutoCheckVersion` |

> ### Две ловушки, на которых ошибается почти любой разбор
>
> **1. `DefaultVersion` приоритетнее `Version`.**
> Дословно: «При последующих запусках будет использоваться именно эта версия, а не та,
> которая указана в параметре `Version`». Интуиция подсказывает обратное — `Version` выглядит
> как «заданная явно». Это неверно.
>
> **2. `Version` может быть неполной.**
> **[Ф]** В рабочем файле встречается `Version=8.3.25` наряду с `8.3.25.1560` и `8.3.25.1633`.
> Сравнение версий строкой на равенство сломается.

**[Д]** Логика `DefaultApp`: если `App=Auto` и `DefaultApp` не указан — запускается тонкий клиент
с ключом `/AppAutoCheckMode`. Если `DefaultApp` задан — запускается указанный в нём клиент,
тоже с `/AppAutoCheckMode`.

### Аутентификация

| Ключ | Значения | Смысл |
| --- | --- | --- |
| `WA` | `1` / `0` | **[Д]** `1` — пытаться аутентифицироваться средствами ОС, при неудаче запросить логин/пароль. `0` — всегда логин/пароль |
| `WSA` | `1` / `0` | **[Д]** То же для аутентификации на веб-сервере (тонкий клиент через веб-сервер, веб-клиент) |

### Соединение

| Ключ | Значения | Смысл |
| --- | --- | --- |
| `ClientConnectionSpeed` | `Normal`, `Low` | **[Д]** Имеет смысл только для тонкого и веб-клиентов. Если не указан — берётся из флажка «Низкая скорость соединения» окна запуска |
| `AdditionalParameters` | строка | **[Д]** Дополнительные параметры запуска из окна свойств базы. Пример: `/TechnicalSpecialistMode` |

### Прокси (только для ws-соединения)

| Ключ | Значения | Смысл |
| --- | --- | --- |
| `UseProxy` | `0` / `1` / `2` | **[Д]** `0` — не использовать, `1` — автоопределение, `2` — явные настройки. Если не указан — автоопределение. Для файлового и клиент-серверного варианта смысла не имеет |
| `PSrv` | адрес | **[Д]** Обязателен только при `UseProxy=2` |
| `PPort` | порт | **[Д]** Обязателен только при `UseProxy=2` |
| `PUser` | имя | **[Д]** Имя пользователя прокси |
| `PPasswd` | base64 | **[Д]** **Зашифрованный** пароль прокси. Пример из документации: `XNKxbVEqnXUCwwk1Urovbo7bZFpG/Zpf6cQ10qVtzpk=` |

> `PPasswd` — единственное зашифрованное поле формата. Алгоритм не документирован **[?]**.
> Расшифровывать не пытаемся: читаем и записываем как непрозрачную строку.

### HTTPS-сертификаты

**[Д]** `HttpsCA` и `HttpsCert` — тип источника сертификатов: `None`, `File`, `Windows`, `Linux`, `macOS`.
`HttpsCAFile`, `HttpsCertFile` — пути к файлам; если тип `File`, а путь пуст или отсутствует, тип
считается `None`. `HttpsCertSelect` — способ выбора сертификата Windows: `Recent`, `Choose`, `Auto`.

### Диагностика ошибок подключения

**[Д]** `StartupErrorHelpURL` — URL гиперссылки «Нужна помощь?» в диалоге ошибки.
`StartupErrorHelpText` — текст-подсказка; может быть простой строкой либо сериализованной
форматированной строкой (`СериализаторXDTO.XMLСтрока`).

### Веб-списки

**[Д]** `WebCommonInfoBaseURL` — адрес интернет-сервиса, из которого база попала в список.
Если из `1cestart.cfg` удалить `InternetService` или `WebCommonInfoBases`, записи, полученные
из удалённых источников, исчезнут из списка.

### Только для мобильного клиента

**[Д]** `ShowInList` (`1`/`0`, по умолчанию `0`), `MobilePublicKey` (MD5 открытого ключа в Base64),
`InternetService`, `WebCommonInfoBases`, `DisplayAuthDialog`, `DisableUseBiometrics`,
`UseBiometrics`, `DisableRememberMe`, `RememberMe`. В десктопном сценарии не встречаются,
но при разборе файла должны сохраняться.

## Секции-группы — недокументированная особенность

**[Ф]** В рабочем файле **6 из 59 секций не имеют ключа `Connect`**. Это узлы дерева, а не базы.
У них `OrderInList=-1`.

```ini
[ClientGroup]               ; ГРУППА — нет Connect
ID=11111111-1111-1111-1111-111111111111
OrderInList=-1
Folder=/
OrderInTree=16640
External=0

[DemoBase]                  ; БАЗА
Connect=File="C:\Bases\Demo";
ID=22222222-2222-2222-2222-222222222222
OrderInList=60.6814814814813
Folder=/ClientGroup
OrderInTree=768
External=0
App=Auto
DefaultApp=ThickClient
AppArch=x86_64
WA=1
Version=8.3.25.1633
```

**Документация помечает `Connect` как обязательный и о секциях-группах не упоминает.**
Признак группы — отсутствие `Connect`. Разбор, который считает каждую секцию базой,
на реальном файле даст 6 фантомных баз без строки соединения.

## Требование к парсеру: round-trip без потерь

Известных ключей — 30+, и это только задокументированные. Платформа пишет их выборочно
(**[Ф]** в рабочем файле встречается 13 из них) и может добавить новые в следующей версии.

Обязательно:

- **сохранять неизвестные ключи** — всё нераспознанное возвращается на место при записи;
- **сохранять порядок** секций и ключей внутри секции;
- **сохранять кодировку** исходного файла и стиль переводов строк;
- модель = типизированные поля + `extra: dict[str, str]`.

Проверка: `serialize(parse(x)) == x` побайтово на реальных файлах.

## Источники списков

**[Д]** Итоговый список собирается из:

1. `%APPDATA%\1C\1CEStart\ibases.v8i` — личный список;
2. файлы из параметра `CommonInfoBases` конфигурационных файлов — общие списки;
3. веб-списки через `InternetService` / `WebCommonInfoBases`.

## Открытые вопросы

| # | Вопрос | Как проверить |
| --- | --- | --- |
| 1 | Держит ли `1cestart.exe` файл заблокированным во время работы | Открыть стартер, попытаться записать |
| 2 | Полный набор ключей, которые платформа дописывает сама | Менять свойства базы в стартере, снимать diff |
| 3 | Правила экранирования кавычек внутри значений `Connect` | Создать базу в каталоге с кавычкой в имени |
| 4 | Что делает штатный стартер с секцией без `Connect`, если добавить её вручную | Эксперимент |
