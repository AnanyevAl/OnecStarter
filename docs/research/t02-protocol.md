> Цель: закрыть открытые вопросы [tasks.md](../tasks.md) § T-02 фактами с реальной машины.

## Подготовка (один раз)

1. Резервная копия списка баз:

   ```powershell
   Copy-Item "$env:APPDATA\1C\1CEStart\ibases.v8i" "$env:APPDATA\1C\1CEStart\ibases.v8i.bak-t02"
   ```

2. Команда снятия фактического процесса (далее — «**снять процесс**»); выполнять,
   пока клиент открыт:

   ```powershell
   Get-CimInstance Win32_Process -Filter "Name='1cv8.exe' OR Name='1cv8c.exe' OR Name='1cv8s.exe'" |
     Select-Object ProcessId, ExecutablePath, CommandLine | Format-List
   ```

3. Снятие копии списка до/после действия (далее — «**diff файла**»):

   ```powershell
   Copy-Item "$env:APPDATA\1C\1CEStart\ibases.v8i" e:\tmp\v8i-before.txt
   # ... действие в штатном стартере ...
   Copy-Item "$env:APPDATA\1C\1CEStart\ibases.v8i" e:\tmp\v8i-after.txt
   git diff --no-index e:\tmp\v8i-before.txt e:\tmp\v8i-after.txt
   ```

4. Все запуски — на тестовой базе (`empty` или специально созданной пустой),
   не на рабочих.

## T-02.1. Разрешение неполной версии

**Вопрос:** `Version=8.3.25` — максимум с этим префиксом или максимум вообще?

1. Убедиться, что установлено ≥2 сборки 8.3.25 и хотя бы одна версия постарше
   (`ls "C:\Program Files\1cv8"`). Зафиксировать список установленных.
2. Тестовой базе в штатном стартере выставить `Version=8.3.25` (или взять базу,
   где уже так).
3. Запустить толстым клиентом через штатный стартер → снять процесс → закрыть.
4. Записать `ExecutablePath`.

**Результат:** **[Ф]** 31.07.2026. Установлены 8.3.10, 8.3.18, 8.3.20, 8.3.22, 8.3.25.1560,
8.3.25.1633, 8.3.27.2214. База `empty` с `Version=8.3.25` запущена штатным стартером →
процесс `C:\Program Files\1cv8\8.3.25.1633\bin\1cv8c.exe`. **Неполная версия разрешается
в максимальную установленную с этим префиксом**, а не в максимум вообще (8.3.27 не выбрана).
Маска `8.3.25` в файле уцелела после перезаписи платформой — в полную версию не развёрнута.
Бонус: командная строка запуска клиента — `ENTERPRISE /IBName"empty" /AppAutoCheckVersion
/AppAutoCheckMode` (по имени базы, не по строке соединения); `WA=1` из `.v8i` в CLI не передан.

## T-02.2. Приоритет `DefaultVersion` над `Version`

1. В `ibases.v8i` (правкой файла при закрытом стартере) выставить тестовой базе
   конфликт: `Version=<сборка А>`, `DefaultVersion=<сборка Б>`.
2. Запустить через штатный стартер → снять процесс → закрыть.
3. Какая сборка в `ExecutablePath`? Изменился ли `DefaultVersion` после запуска
   (diff файла)?

**Результат:** **[Ф]** 31.07.2026, два запуска базы `empty`.

| `Version` | `DefaultVersion` | Запустилось |
| --- | --- | --- |
| `8.3.25.1560` (точная) | `8.3.25.1633` | **8.3.25.1560** — победила `Version` |
| `8.3.25` (маска) | `8.3.25.1560` | **8.3.25.1560** — победила `DefaultVersion` |

**Итоговая семантика выбора версии:** точная `Version` → используется она, `DefaultVersion`
игнорируется; неполная `Version` + `DefaultVersion` → используется `DefaultVersion`;
неполная `Version` без `DefaultVersion` → максимум установленных с этим префиксом (T-02.1).

Утверждение ИТС «при последующих запусках будет использоваться именно `DefaultVersion`,
а не `Version`» **опровергнуто** для случая точной `Version`.

**Не проверено:** `DefaultVersion` вне маски (`Version=8.3.25` + `DefaultVersion=8.3.22.1923`) —
уточняет ли он маску, если ей не соответствует.

## T-02.3. `Folder` у секции-группы, вложенные группы

1. Diff файла вокруг действия: в штатном стартере создать группу `T02` в корне,
   в ней подгруппу `T02-вложенная`, перенести туда тестовую базу.
2. Записать: как выглядят секции обеих групп (`Folder`, `OrderInTree`), что
   в `Folder` у базы; допускает ли стартер группы второго уровня вообще.

**Результат:** **[Ф]** 31.07.2026, два источника.

Из наблюдения за реальным файлом: секция-группа `[группа-вложенная]` имеет
`Folder=/группа-родитель`, а базы внутри неё — `Folder=/группа-родитель/группа-вложенная`.

Из эксперимента (мастер стартера пройден UI Automation, вечерняя сессия): в мастере
«Добавить…» есть пункт **«Создание новой группы»**. Создана группа `T02` в корне и
подгруппа `T02-вложенная` внутри неё — **группы второго уровня стартер допускает**.
Записанные секции:

```ini
[T02]
ID=21ec0cc2-e00e-4b7f-8a5d-dd723f64f7f0
OrderInList=-1
Folder=/
OrderInTree=24960
External=0
[T02-вложенная]
ID=e31b75c0-f13f-4626-8d4c-e499665e70fb
OrderInList=-1
Folder=/T02
OrderInTree=256
External=0
```

**Подтверждено:** у секции-группы `Folder` — путь **родителя**, собственный путь группы =
`Folder` + `/` + имя секции; `Connect` у группы отсутствует. Секция группы дописывается
в конец файла **сразу** по завершении мастера, без перезаписи остального файла.

Не проверено: перенос базы в группу (в мастере «Изменить…» поля папки нет — только
drag&drop в дереве; семантика `Folder` базы уже подтверждена реальным файлом).

## T-02.4. Блокировка `ibases.v8i` штатным стартером

1. Открыть окно штатного стартера `1cestart.exe`, не закрывать.
2. Попытаться записать файл:

   ```powershell
   Add-Content "$env:APPDATA\1C\1CEStart\ibases.v8i" ""
   ```

3. Повторить при открытом окне выбора базы и при запущенном клиенте.
   Записать, в каком состоянии запись отвергается (если вообще).

**Результат:** **[Ф]** 31.07.2026. **Блокировки нет ни в одном состоянии.** При открытом окне
`1cestart.exe` и при работающем клиенте `1cv8c.exe` успешны и открытие файла на запись
(`r+b`), и атомарная замена (`tempfile` + `Path.replace`). Наши правки, сделанные до открытия
стартера, стартер не затирал при открытии окна — массовая перезапись происходит по другому
событию (см. побочные наблюдения).

## T-02.5. Ключи, которые платформа дописывает сама

1. Diff файла вокруг каждого действия по отдельности: изменить имя базы; изменить
   версию в свойствах; изменить «основной режим запуска»; просто запустить и
   закрыть клиент.
2. Записать полный список появившихся/изменённых ключей по каждому действию.
   Отдельно: пережил ли ручной посторонний ключ (`XTest=1`, вписать заранее)
   перезапись стартером.

**Результат (частично):** **[Ф]** 31.07.2026, по diff'ам вокруг запусков. Платформа сама
дописывает: `AppArch` (переносится в конец секции), `DisableLocalSpeechToText=0` (**всем**
секциям сразу, в одном сеансе — ключ версии 8.3.27, документации по нему у нас нет),
`DefaultVersion` (значение — запрошенная версия, см. T-02.8), `DefaultApp` (у части баз,
`ThickClient`), `OrderInList`/`OrderInTree` (пересчёт).

**[Ф]** 31.07.2026 (вечерняя сессия): посторонний ключ `XTest=1`, вписанный в секцию
`[empty]`, **пережил** полную каноническую перезапись файла платформой — перенесён в самый
конец секции (после `AppArch`), значение сохранено. Неизвестные ключи платформа не удаляет.

**Отдельная находка — что именно является событием перезаписи.** Запуск
`1cestart.exe ENTERPRISE /IBName"..."` из командной строки **не трогает файл вообще** —
ни при закрытии на диалоге логина, ни после полного цикла «вход → работа → штатное
закрытие» (diff пуст, `DefaultVersion` не дописан). Полная каноническая перезапись
происходит при запуске базы **из окна стартера** (выбор в списке + кнопка
«1С:Предприятие»). `DefaultVersion` при этом для маски `Version=8.3.25` **не** записан —
т.е. платформа пишет его не при каждом запуске (в T-02.8 писала при несуществующей
версии). Выход из окна стартера без действий файл тоже не переписывает.

## T-02.6. Исполняемый файл тонкого клиента файловой базы

1. Тестовой файловой базе выставить режим «тонкий клиент».
2. Запустить через штатный стартер → снять процесс → закрыть.
3. Записать имя exe: `1cv8c.exe` или `1cv8s.exe`.

**Результат:** **[Ф]** 31.07.2026. Файловая база `empty` с `App=Auto` →
`1cv8c.exe` (тонкий клиент), не `1cv8s.exe`. Вечерняя сессия: явный `App=ThinClient` →
тоже **`1cv8c.exe`** (`C:\Program Files\1cv8\8.3.25.1633\bin\1cv8c.exe`).

**Отдельная находка:** при явном `App=ThinClient` стартер собрал командную строку
**без `/AppAutoCheckMode`** (`ENTERPRISE /IBName"empty" /AppAutoCheckVersion`), а при
`App=Auto` — с ним. Т.е. `/AppAutoCheckMode` передаётся только когда клиент выбирается
автоматически.

## T-02.7. Воспроизведение `WA=1` командной строкой

1. На базе с ОС-аутентификацией, где текущий пользователь ОС **не** сопоставлен
   пользователю ИБ, запустить: `1cv8c.exe ENTERPRISE /F<путь> /WA+` — записать
   поведение (ошибка? диалог логина?).
2. То же с `/WA-` и без ключа вовсе.
3. Записать, чем отличается от поведения штатного стартера при `WA=1` в `.v8i`.

**Результат (частично):** **[Ф]** 31.07.2026. У базы `empty` в `.v8i` стоит `WA=1`.
В командной строке клиента ключей `/WA` **нет вообще** (снято дважды):
`ENTERPRISE /IBName"empty" /AppAutoCheckVersion /AppAutoCheckMode`. При этом клиент показал
диалог логина/пароля — то есть поведение «пытаться ОС-аутентификацию, при неудаче спросить»
реализовано платформой при запуске **по имени базы** (`/IBName`), а не ключами `/WA`.

**Следствие для архитектуры:** при запуске по имени базы через `/IBName` семантика `WA=1`
достаётся нам бесплатно — воспроизводить откат самим не нужно. Открытый вопрос переносится
на сценарий запуска по строке соединения (`/F`, `/S`), где `.v8i` не участвует.

**[Ф]** 31.07.2026 (вечерняя сессия): запуск `1cv8c.exe ENTERPRISE /F"D:\db\empty"` с
`/WA+`, с `/WA-` и без ключа — во всех трёх случаях одинаковый диалог
«Доступ к информационной базе» (логин/пароль), ошибки нет. Оговорка: в `empty`
нет пользователей с настроенной ОС-аутентификацией, поэтому «обязательность» `/WA+`
проявиться не на ком — при недоступной ОС-аутентификации `/WA+` не падает с ошибкой,
а показывает диалог.

Осталось непроверенным: `/WA+` на базе, где у пользователей ИБ настроено сопоставление
с пользователями ОС (требует настройки в Конфигураторе).

## T-02.8. Несуществующая версия при выключенной автоустановке

1. В `1cestart.cfg` проверить/выставить `AppAutoInstallLastVersion=0`
   (заранее сохранить исходное значение).
2. Тестовой базе выставить `Version=8.3.99.1`.
3. Запустить через штатный стартер. Записать: сообщение об ошибке, или запуск
   другой версией (какой — снять процесс), или диалог.
4. Вернуть `1cestart.cfg` как было.

**Результат:** **[Ф]** 31.07.2026. `1cestart.cfg` уже содержал `AppAutoInstallLastVersion=0`
(менять не пришлось; там же `UseHWLicenses=0` и `ConfigurationTemplatesLocation` с локальным
путём к шаблонам).
База `empty` с `Version=8.3.99.1` без `DefaultVersion` запустилась **молча** версией
`8.3.27.2214` — максимальной установленной **вообще**, без предупреждения о несуществующей
версии. Это подтверждает боль А из требований: расхождение версии штатный стартер не
показывает.

**Отдельная находка:** после запуска платформа записала `DefaultVersion=8.3.99.1` — то есть
**запрошенную** версию, а не фактически запущенную `8.3.27.2214`. Второе опровержение
формулировки ИТС о `DefaultVersion` как «версии, реально использованной при последнем запуске».

## T-02.9 (опционально). Пробелы вокруг `=` в ключах

**Вопрос из финального ревью плана 1:** видит ли штатный стартер базу, если в её
секции написать `Connect = File="..."` (пробелы вокруг `=`)?

1. При закрытом стартере вписать тестовой базе пробелы вокруг `=` у `Connect`.
2. Открыть стартер: база видна? запускается? Что стало с пробелами после
   перезаписи файла стартером (diff)?

**Результат:** **[Ф]** 31.07.2026 (вечерняя сессия). Пробелы вокруг `=` **не допускаются**,
и это разрушительно:

1. С `Connect = File="D:\db\empty";` секция `empty` отображается в стартере
   **как группа** (значок папки) — ключ `Connect␣` с пробелом в имени не распознан
   как `Connect`, а секция без `Connect` считается группой.
2. Запуск такой «группы» кнопкой «1С:Предприятие» запустил `1cv8s.exe`
   **максимальной установленной версии вообще** (8.3.27.2214) с пустой строкой
   соединения: `"" /AppAutoCheckVersion /AppAutoInstallLastVersion-` (двумя процессами).
   `Version` секции проигнорирован — секция не считается базой.
3. После перезаписи платформой строка с пробелами **сохранена как посторонний ключ**
   (перенесена в конец секции, как `XTest=1`), а базовые ключи `App`, `WA`, `Version`,
   `AppArch` из секции **удалены** — платформа вычистила их как не относящиеся к группе.
   Порча необратима: «база» деградирует до группы с мусорным ключом.

**Следствие для парсера:** ключи сравниваются байт-в-байт, пробелы не тримить —
`Connect␣` ≠ `Connect`. Поведение нашего разбора должно совпадать с платформенным,
иначе мы «увидим» базу там, где стартер видит группу.

## Побочные наблюдения 31.07.2026 (запуск `empty` через штатный стартер, платформа 8.3.25.1633)

Все — **[Ф]**, сняты diff'ом `ibases.v8i` до/после одного запуска:

1. **Файл переписан с BOM UTF-8.** До — UTF-8 без BOM, после — с BOM. Утверждение скила
   «UTF-8 без BOM» требует уточнения: в природе оба варианта, платформа меняет кодировку
   при перезаписи.
2. **Файл переписывается целиком в каноническом порядке платформы:** `AppArch` перенесён
   в конец каждой секции; у баз с `OrderInList=-1` материализованы значения
   (196608…1081344) и секции перемещены в конец файла; `OrderInTree` пересчитан у многих
   секций. Опора на порядок секций/ключей между сеансами невозможна — слияние только по `ID`.
3. **`DefaultVersion` и `DefaultApp` НЕ записаны** базе `empty` после запуска и штатного
   закрытия клиента (ожидание из ИТС не подтвердилось в этом сценарии — см. T-02.2).
4. Правка файла сторонним процессом (нашей библиотекой) до открытия стартера пережила
   последующую перезапись: изменённое значение `Version` сохранено.
