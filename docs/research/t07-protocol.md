# Протокол экспериментов T-07 — серверная механика перед планом v2

> Цель: закрыть вопросы [tasks.md](../tasks.md) § T-07 фактами с реальной машины
> до плана реализации v2 «Серверы» ([спека](../superpowers/specs/2026-08-26-v2-servers-design.md),
> §10). Каждый результат записывается в этот файл в поле «Результат»;
> подтверждённое уходит в новый скил `server-launch` с меткой **[Ф]**,
> опровергнутое исправляет спеку (правило: переписывается правило, а не
> подгоняется код). Поле «Куда» у каждого эксперимента.
>
> **Запуск серверных процессов выполняет заказчик или агент по явной команде
> на каждый запуск** — правило «Границы» `CLAUDE.md`. Все эксперименты идут
> на одноразовых каталогах кластера в `e:\tmp\t07\` и нестандартных портах
> (2540+), чтобы не задеть ни рабочие кластеры (`E:/work-spaces/srv/…`),
> ни возможные службы на штатных 1540/1541. Рабочие каталоги кластеров
> не трогать ни одним шагом.
>
> Перед блоками А–Б: сверить ожидания с ИТС-приложениями в `temp/`
> («Приложение 3. Описание и расположение служебных файлов» — srvinfo и
> расположение логов) и записать в «Ожидание» метку [Д], где приложение
> вопрос покрывает.

## Подготовка (один раз)

1. Каталог экспериментов: `New-Item -ItemType Directory -Force e:\tmp\t07`.
2. «**Снять серверные процессы**»:

   ```powershell
   Get-CimInstance Win32_Process -Filter "Name='ragent.exe' OR Name='rmngr.exe' OR Name='rphost.exe'" |
     Select-Object ProcessId, ParentProcessId, CreationDate, ExecutablePath, CommandLine | Format-List
   ```

3. «**Запуск подопытного ragent**» (версия — любая установленная с сервером,
   уточняется по T-07.10; порты сдвинуты, каталог одноразовый):

   ```powershell
   & "C:\Program Files\1cv8\<версия>\bin\ragent.exe" -debug -http -port 2540 -regport 2541 -range 2560:2591 -d e:\tmp\t07\srv1
   ```

4. Проверка живости: снятие процессов из п. 2 + `Test-NetConnection localhost -Port 2540`.
5. После каждого эксперимента: остановить подопытные процессы, каталог
   `e:\tmp\t07\srv*` удалить (или сохранить как артефакт шага, если результат
   в нём).

## Блок В — сканирование процессов (T-07.6, 7, 13)

### В1. Видимость argv служб (T-07.6)

Вопрос: возвращает ли механизм скана командную строку процесса SYSTEM
(службы) без повышения: строка / отказ / пусто.

Шаги: если на машине есть штатная служба агента сервера — снять её
командную строку п. 2 из-под обычного пользователя. Если службы нет —
создать одноразовую (потребует повышения; шаг опционален и по решению
заказчика) либо пометить вопрос открытым до машины со службой.

Результат (частично): **[Ф] 26.08.2026, агентом, WMI без повышения**
(`elevated: False`): у процессов SYSTEM-класса (`winlogon`, `services`,
`lsass`, `svchost` — 106 штук) `CommandLine` и `ExecutablePath`
**не видны**, `CreationDate` видна. Следствие для ragent-службы:
сопоставление по `-d` и версия из пути exe без повышения недоступны.
[Р] Ограничение уровня ОС, а не WMI: чтение командной строки процесса
другого пользователя требует прав, другие механизмы упрутся в то же.
Осталось: подтвердить на настоящей службе агента сервера (в т.ч. под
выделенным пользователем, не SYSTEM).

Куда: выбор `ProcessScanner` — спека §4.2; статус «служба» §3.1;
**спека §3.1/§3.3/§6.3 правлены вслед за находкой 26.08.2026** —
непрозрачный ragent не сопоставляется и показывается ограниченно.

### В3. Механизм скана (T-07.13)

Вопрос: psutil / WMI (`Get-CimInstance` подпроцессом) / WinAPI — по
критериям: вес PyInstaller-сборки, реакция антивирусов (requirements §6),
точность argv (совместимость разбора с `CommandLineToArgvW`,
кавычки/слэши), видимость служб (В1), стоимость одного скана
(для периода §4.4).

Шаги: прототипы на настольной машине без 1С-процессов (замер стоимости —
на подставном процессе с ragent-подобной строкой); сборка smoke с

Результат (частично): **[Ф] 26.08.2026, агентом.** Стоимость

снимок 673 процессов ~788 мс. Для периода ~5 с это дорого (≈16% времени
в снимке), а подпроцесс PowerShell добавит своё. Вывод: WMI на каждый
тик — слабый кандидат; замер psutil и WinAPI остаётся, как и вес
сборки/антивирусы.

Куда: реализация `ProcessScanner`; период скана §4.4; риск №1 дизайна.

## Блок Г — консоль администрирования (T-07.8, 9, 10)

### Г1. Наличие серверных компонент (T-07.10)

машины заказчика; отличается ли состав у «клиентских» установок.

Шаги (без запуска 1С, можно агентом):

```powershell
Get-ChildItem "C:\Program Files\1cv8" -Directory |
  ForEach-Object { [pscustomobject]@{
    Version = $_.Name
    ragent  = Test-Path "$($_.FullName)\bin\ragent.exe"
    radmin  = Test-Path "$($_.FullName)\bin\radmin.dll"
  } }
Test-Path "C:\Program Files\1cv8\common\1CV8 Servers (x86-64).msc"
```

Результат: **[Ф] 26.08.2026, машина заказчика, агентом.** Все семь
установленных версий (8.3.10.2252 … 8.3.27.2214) несут `ragent.exe`,
`radmin.dll` **и `ras.exe`** (попутная находка — пригодится Г3).
`common\1CV8 Servers (x86-64).msc` существует и единственный; состав
`common`: `1cestart.exe`, `1ceunt.dll`, `.msc`, `haspdinst.exe`.
Оговорка: установки без серверных компонент на этой машине нет, вопрос
