## Подготовка (один раз)

1. Резервные копии:

   ```powershell
   Copy-Item "$env:APPDATA\1C\1CEStart\ibases.v8i" "$env:APPDATA\1C\1CEStart\ibases.v8i.bak-t05"
   Copy-Item "$env:APPDATA\1C\1CEStart\1cestart.cfg" "$env:APPDATA\1C\1CEStart\1cestart.cfg.bak-t05"
   ```

2. «**Снять процесс**» (выполнять, пока клиент открыт):

   ```powershell
   Get-CimInstance Win32_Process -Filter "Name='1cv8.exe' OR Name='1cv8c.exe' OR Name='1cv8s.exe'" |
     Select-Object ProcessId, ExecutablePath, CommandLine | Format-List
   ```

3. «**Diff файла**»:

   ```powershell
   Copy-Item "$env:APPDATA\1C\1CEStart\ibases.v8i" e:\tmp\v8i-before.txt
   # ... действие ...
   Copy-Item "$env:APPDATA\1C\1CEStart\ibases.v8i" e:\tmp\v8i-after.txt
   git diff --no-index e:\tmp\v8i-before.txt e:\tmp\v8i-after.txt
   ```

4. «**Прямой запуск**» клиента: PowerShell съедает кавычки внутри аргументов,
   поэтому канонично через `cmd` (вся строка — в одинарных кавычках PS):

   ```powershell
   cmd /c '"C:\Program Files\1cv8\8.3.25.1633\bin\1cv8c.exe" ENTERPRISE /IBName"empty" /AppAutoCheckVersion /AppAutoCheckMode'
   ```

5. Тестовая база — `empty` (**[Ф]** T-02: файловая, `D:\db\empty`, пользователь «Админ»
   с пустым паролем, в секции `WA=1`). Установленные версии (**[Ф]** T-02.1): 8.3.10.2252,
   8.3.18.1334, 8.3.20.2290, 8.3.22.1923, 8.3.25.1560, 8.3.25.1633, 8.3.27.2214.
   Рабочие базы не трогать; для экспериментов отображения (Б) допустима секция-пустышка
   с `Connect=File="D:\db\t05-нет";` — её не запускать, только смотреть в стартере.
6. Все правки `ibases.v8i` и `1cestart.cfg` — при закрытом стартере. `1cestart.cfg` —
   **UTF-16LE с BOM** (скил `platform-launch`): править редактором, сохраняющим кодировку,
   diff после правки обязателен.

## Блок А — запуск

### T-05.1. Форма присоединения значения к `/IBConnectionString`

**Вопрос:** как клиент принимает строку соединения из командной строки.
**Сейчас в коде:** `/IBConnectionString"<connect>"` с удвоением внутренних кавычек —
принято **по аналогии** со снятой формой `/IBName` (решение 1 плана 2, допущение
помечено в `src/onecstarter/domain/launch.py`, `build_arguments`). Косвенный намёк
против: **[Ф]** T-02.9 — при запуске «группы» стартер передал строку соединения
**позиционным** аргументом (`"" /AppAutoCheckVersion ...`), без ключа вовсе.

1. Прямой запуск нашей формы (кавычки внутри `Connect` удвоены):

   ```powershell
   cmd /c '"C:\Program Files\1cv8\8.3.25.1633\bin\1cv8c.exe" ENTERPRISE /IBConnectionString"File=""D:\db\empty"";" /AppAutoCheckVersion'
   ```

2. Критерий успеха: открылась именно `empty` (диалог «Доступ к информационной базе»
   либо окно базы) → снять процесс → закрыть.
3. Если ошибка параметра/пустой запуск — варианты по одному, фиксируя исход каждого:
   ключ и значение через пробел (`/IBConnectionString "File=..."`); позиционная форма
   без ключа (`"File=""D:\db\empty"";"` сразу после `ENTERPRISE`); без удвоения кавычек.
4. Отдельно: путь с пробелом (скопировать `D:\db\empty` в `D:\db\t05 пробел`,
   повторить рабочую форму, каталог потом удалить).

**Куда:** `domain/launch.py` (`build_arguments`) + `tests/unit/test_launch.py`;
скил `platform-launch` (`reference.md`, раздел ключей клиента).

**Результат:** **[Ф]** 05.08.2026, агент, платформа 8.3.25.1633. **Наша форма верна.**
Запуск `/IBConnectionString"File=""D:\db\empty"";"` (значение прижато к ключу, внутренние
кавычки удвоены) → клиент загрузил конфигурационную информацию и показал диалог
«Доступ к информационной базе» — база найдена и открыта. Путь с пробелом
(`D:\db\t05 пробел`) — тот же результат. Альтернативные формы проверять не пришлось.
Побочно: запуск по строке соединения `ibases.v8i` не меняет (хеш до/после, снято
до входа). Код правок не требует, допущение в `build_arguments` снять.

### T-05.2. Находит ли `/IBName` базу из общего списка

**Вопрос:** объединяет ли клиент при запуске по `/IBName` пользовательский список
с `CommonInfoBases`. **Сейчас в коде:** [Р, не проверено] дизайн плана 3 §7 — принято,
что объединяет; `services/launch.py` запускает записи из общих списков тем же путём.

1. Создать `e:\tmp\t05-common.v8i` (UTF-8) с секцией, которой **нет** в `ibases.v8i`:

   ```ini
   [T05-Общая]
   Connect=File="D:\db\empty";
   ID=<новый GUID>
   ```

2. В `1cestart.cfg` дописать строку `CommonInfoBases=e:\tmp\t05-common.v8i`
   (кодировку файла сохранить, п. 6 подготовки).
3. Прямой запуск: `... 1cv8c.exe ENTERPRISE /IBName"T05-Общая" /AppAutoCheckVersion`.
   Открылась ли база? Снять процесс.
4. Побочно: открыть окно стартера — видна ли `T05-Общая` в списке; закрыть без запуска.
5. Убрать строку из `1cestart.cfg`, удалить `e:\tmp\t05-common.v8i`.

**Куда:** докстринг `services/launch.py`; обязательства плана UI (ветка общих списков);
скил `platform-launch`.

**Результат:** **[Ф]** 05.08.2026, агент. **Находит.** `1cv8c.exe ENTERPRISE
/IBName"T05-Общая"` открыл базу, существовавшую только в `CommonInfoBases` —
клиент объединяет пользовательский список с общими; допущение [Р] плана 3 §7
подтверждено, `services.launch` работает для общих записей без правок.

Три находки сверх вопроса:

1. **Клиент материализовал общую запись в `ibases.v8i`**: секция скопирована
   с тем же `ID`, дописаны `App=Auto`, `WA=1`, `OrderInList`/`OrderInTree`
   и **`External=1`** (у локальных записей `External=0`) — семантика ключа
   `External` прояснилась. `Version` не скопирован. Значит дубль
   «пользовательский + общий» — штатное состояние после первого запуска,
   и дедупликация T-04.4 по `ID` — единственно верная стратегия.
2. **Материализация прошла полной канонической перезаписью файла прямым
   клиентом `1cv8c.exe`** (не стартером): `DisableLocalSpeechToText=0` всем
   секциям, пустые строки-разделители убраны, `OrderInList=-1` материализован.
   Прежний факт «CLI-запуск файл не трогает» относился к `1cestart.exe`.
   При этом полный цикл по `/IBName` базы пользовательского списка
   (вход → сеанс → штатное закрытие) файл **не** меняет — перезапись именно
   от материализации.
3. **Отказ — не ошибка.** После удаления `CommonInfoBases` и материализованной
   секции тот же запуск дал **окно выбора информационных баз** («Запуск
   1С:Предприятия», список, кнопки), а не сообщение об ошибке. Ненайденное имя
   клиент молча превращает в диалог выбора — наши проверки до запуска обязаны
   ловить «имя не найдено» сами, от платформы диагностики не будет.

### T-05.3. `/IBName` при дублях имён; регистр имени

**Вопрос:** что делает клиент при нескольких базах с одним именем, и учитывается ли
регистр при сопоставлении имени. **Сейчас в коде:** guard `_reject_ambiguous_name`
в `services/workspace.py` отказывает до запуска ([Д] «платформа прекращает запуск
с ошибкой» — экспериментально не снималось); сравнение имён **точное**, регистр
помечен [не проверено].

1. При закрытом стартере вписать в `ibases.v8i` две секции `[T05-Дубль]`
   с разными `Connect` (обе можно на `D:\db\empty` — формат это допускает)
   и разными `ID`.
2. Прямой запуск `/IBName"T05-Дубль"` → записать поведение: ошибка (текст?),
   запуск первой, диалог выбора?
3. Переименовать вторую секцию в `[t05-дубль]` (только регистр) → прямой запуск
   `/IBName"T05-Дубль"` → конфликт или однозначный запуск?
4. Удалить вторую секцию. Прямой запуск `/IBName"t05-дубль"` (регистр не совпадает
   с оставшейся `[T05-Дубль]`) → находит или «база не найдена»?
5. Убрать тестовые секции.

**Куда:** `services/workspace.py` (`_reject_ambiguous_name`) + тесты;
скил `platform-launch`.

**Результат:** **[Ф]** 05.08.2026, агент. Сопоставление имени **регистронезависимое**,
дубли пресекаются самим клиентом:

- две секции `[T05-Дубль]` с разными `Connect` → сообщение **«Не уникальное имя
  информационной базы "T05-Дубль"»**, запуск прекращён — [Д] подтверждён;
- `[T05-Дубль]` + `[t05-дубль]` (различие только регистром) → **та же ошибка**;
- единственная `[T05-Дубль]`, запрос `/IBName"t05-дубль"` → база **найдена**,
  диалог доступа.

**Код требует правки:** `_reject_ambiguous_name` сравнивает имена точно и пропускает
конфликт, который платформа считает дублем, — пользователь получит ошибку платформы
вместо нашей диагностики. Сравнение перевести на casefold; довод докстринга «лишний
отказ хуже пропуска» снят — отказ по casefold ложным не бывает, платформа откажет
всё равно.

### T-05.4. Держит ли `/AppAutoCheckVersion-` нашу версию

**Вопрос:** остаётся ли работать запущенный нами exe, когда `Version` секции просит
другую версию. Это фундамент всей модели запуска `services/launch`: версию разрешаем
сами и передаём `/AppAutoCheckVersion-`; [Д] «иначе платформа переиграет выбор» —
самим ключом эксперимент не снимался, и если платформа переигрывает выбор даже
с ним, показанная в UI версия будет ложью.

1. Базе `empty` выставить `Version=8.3.22.1923` (установлена, точная).
2. Прямой запуск **exe 8.3.25.1633** с `/AppAutoCheckVersion-`:

   ```powershell
   cmd /c '"C:\Program Files\1cv8\8.3.25.1633\bin\1cv8c.exe" ENTERPRISE /IBName"empty" /AppAutoCheckVersion-'
   ```

   Снять процесс: `ExecutablePath` остался `8.3.25.1633`? Появился ли второй процесс
   другой версии?
3. То же с `/AppAutoCheckVersion` (включённым): перезапустила ли платформа клиента
   версии `8.3.22.1923`? Снять процесс.
4. Вернуть `Version` секции как было.

**Куда:** подтверждение модели `services/launch.py`; скил `platform-launch`
(алгоритм подбора версии, [Д] → [Ф] или правка).

**Результат:** **[Ф]** 05.08.2026, агент. Секции `empty` выставлен
`Version=8.3.22.1923`, запускался exe `8.3.25.1633\bin\1cv8c.exe`:

- с `/AppAutoCheckVersion-` — работает **один** процесс `8.3.25.1633`,
  наша версия удержана;
- с `/AppAutoCheckVersion` — наш процесс завершился, платформа перезапустила
  клиента `8.3.22.1923\bin\1cv8c.exe` с командной строкой
  `ENTERPRISE /IBName"empty" /AppAutoCheckMode /AppAutoCheckVersion`
  (ключ `/AppAutoCheckMode` она добавила сама).

Модель запуска `services/launch` подтверждена с обеих сторон: версия, показанная
в UI, совпадает с фактической только при `/AppAutoCheckVersion-`. Код правок
не требует, [Д] в скиле повышается до [Ф].

### T-05.5. `DefaultVersion` вне маски `Version`

**Вопрос:** остаток T-02.2 — уточняет ли `DefaultVersion` маску, которой
не соответствует. **Сейчас в коде:** `domain/selection.py` игнорирует
`DefaultVersion`, не начинающийся с маски (`starts_with`) либо не установленный,
и идёт дальше по цепочке — поведение платформы в этих случаях не снималось.

1. Базе `empty` выставить `Version=8.3.25`, `DefaultVersion=8.3.22.1923` (вне маски).
2. Запуск **из окна стартера** (важно: решать должна платформа, не наша команда) →
   снять процесс: 8.3.22.1923 (уточнил вне маски) или 8.3.25.1633 (маска победила)?
3. Опционально: `DefaultVersion=8.3.25.9999` (в маске, но не установлен) → запуск
   из окна стартера → что запустилось; появилось ли сообщение.
4. Вернуть ключи секции; diff файла после каждого шага (запуск из окна стартера
   перезаписывает файл целиком — **[Ф]** T-02.5).

**Куда:** `domain/selection.py` (`resolve_version`) + табличные тесты;
скилы `platform-launch` и `v8i-format` (факт 3).

**Результат:** **[Ф]** 05.08.2026, агент. Вместо окна стартера использован
эквивалентный CLI-путь `1cestart.exe ENTERPRISE /IBName"empty"` — версию выбирает
тот же стартер (окно оказалось небезопасно автоматизировать, см. журнал ниже).
Секция `empty`, `Version=8.3.25` (маска):

- `DefaultVersion=8.3.22.1923` (установлен, **вне маски**) → запущен
  **`8.3.22.1923`**. `DefaultVersion` побеждает маску, даже когда
  ей не соответствует.
- `DefaultVersion=8.3.25.9999` (в маске, **не установлен**) → запущен
  **`8.3.27.2214`** — молча максимум установленных **вообще**, маска
  не ограничила фолбэк (prefix-max `8.3.25.1633` не выбран).
  `DefaultVersion` в файле остался `8.3.25.9999` — запрошенным (ещё одно
  подтверждение T-02.8).

**Код требует решения:** `resolve_version` в первом случае игнорирует
`DefaultVersion` вне маски (проверка `starts_with`), во втором — падает
на prefix-max; платформа в обоих случаях делает другое. Минимум — поле
`fallback` («что молча запустил бы штатный стартер») обязано считаться
по платформенным правилам, иначе UI-подсказка врёт. Расширить табличные
тесты `test_selection.py` этими двумя строками.

Побочные наблюдения:

1. **Окно списка баз рисует не `1cestart.exe`.** Он мгновенно завершается,
   делегируя окно `1cv8s.exe` **максимальной установленной версии** с пустой
   строкой соединения (`"" /AppAutoCheckVersion /AppAutoInstallLastVersion-`) —
   это объясняет «двухпроцессный» след T-02.9.
2. Кнопка «1С:Предприятие» окна выбора запускает **выделенную в списке** базу;
   попытка выбрать нужную через UI Automation не сработала (SelectionItemPattern
   не поддержан списком 1С), и кнопка запустила ранее выделенную рабочую базу —
   клиент убит на диалоге аутентификации, в базу не входили. Автоматизация окна
   стартера ненадёжна — для GUI-экспериментов блока Б нужен человек за машиной.

## Блок Б — формат `.v8i` и группы

### T-05.6. Пустой `Connect=` — группа или база

**Вопрос:** трактовка секции с ключом `Connect` без значения (план 3 §7).
**Сейчас в коде:** признак группы — **отсутствие** `Connect`; `Connect=` с пустым
значением наш разбор считает базой. Сюда же — теоретический ложный отказ backstop-а
групп (отложено финальным ревью ветки плана 4).

1. При закрытом стартере вписать секцию:

   ```ini
   [T05-ПустойConnect]
   Connect=
   ID=<новый GUID>
   Version=8.3.25
   ```

2. Открыть стартер: значок папки или базы? Закрыть без запуска.
3. Запустить любую другую базу из окна стартера (событие полной перезаписи) →
   diff файла: секция уцелела? `Version` вычищен, как у деградировавшей базы
   в T-02.9, или сохранён?
4. Убрать секцию.

**Куда:** `config/v8i.py` (`is_group`) при расхождении; заметка backstop-а
в `services/groups.py`; скил `v8i-format` (факт 2).

**Результат:** **[Ф]** 05.08.2026, заказчик у стартера + агент (diff'ы). **Пустой
`Connect=` — группа.** Стартер показал секцию значком группы, а первая же полная
перезапись (запуск `empty` из окна) **довершила деградацию**: ключ `Connect=`
удалён, `Version` вычищен, дописаны групповые `OrderInList=-1`, `Folder=/`,
`OrderInTree`, `External=0` — секция превращена в группу необратимо, как
«испорченная» база T-02.9/факта 6 скила.

**Код требует правки:** наш `is_group` считает признаком группы **отсутствие**
ключа `Connect`; секцию с `Connect=` (ключ есть, значение пустое) разбор трактует
как базу — расхождение с платформой. Признак группы: `Connect` отсутствует
**или пуст**.

### T-05.7. Регистр при сопоставлении `Folder` с именем группы

**Вопрос:** `Folder=/t05-группа` при группе `[T05-Группа]` — внутри группы или мимо?
**Сейчас в коде:** сравнение путей в `services/paths.py` регистрозависимое,
а `binding_key` приводит путь группы к нижнему регистру — расхождение зафиксировано
финальным ревью ветки плана 4 и ждёт именно этого факта.

1. Мастером стартера создать группу `T05-Группа` в корне.
2. При закрытом стартере вписать пустышку с `Folder` в другом регистре:

   ```ini
   [T05-Пустышка]
   ```
