# T-30 / T-32 — вход по ОС и ключ `WA`: протокол эксперимента

Для заказчика. Проводится на любой машине с установленной платформой 1С 8.3, где можно
завести тестовую файловую базу. Рабочие базы не нужны и не затрагиваются.

## Что выясняем

1. **T-30.** Снятый флажок «Аутентификация ОС» в OneCStarter **удаляет** ключ `WA` из
   `ibases.v8i`, а не пишет `WA=0`. Работает ли он вообще, зависит от того, как платформа
   понимает отсутствие ключа, — это не измерено.
2. **T-32.** Можно ли ключом `/WA-` заставить платформу показать диалог входа, когда
   в `.v8i` стоит `WA=1` и вход по учётной записи Windows настроен. Подставляет ли
   платформа имя из `/N` в диалог, если пароль не передан.
3. Что пишет в `WA` штатный стартер и как у него называется этот выбор.

## Подготовка (один раз)

Закройте OneCStarter и штатный стартер: оба могут перезаписать `ibases.v8i` во время опыта.

1. **Тестовая база.** В штатном стартере: «Добавить» → создание новой информационной базы →
   **без конфигурации** → файловая. Имя в списке — ровно `Тест ОС` (скрипт ищет секцию
   по имени).
2. **Пользователи.** Откройте базу в конфигураторе → «Администрирование» → «Пользователи».
   Заведите двух:

   | Пользователь | Аутентификация 1С:Предприятия | Аутентификация операционной системы |
   | --- | --- | --- |
   | `osuser` | выключена | **включена**, пользователь ОС — ваша текущая учётная запись Windows (кнопка выбора у поля) |
   | `tester` | **включена**, пароль `1` | выключена |

   Названия пунктов приведены по памяти, не сверены с экраном (**[?]**). Если у вас они
   называются иначе — запишите, как именно, в раздел «Заметки» файла результатов.
3. **Скрипт.** Скопируйте на машину оба файла: `t30-os-auth-matrix.ps1` и `t30-results.md`,
   в один каталог. Откройте в нём PowerShell. Если скрипты запрещены политикой:
   `powershell -ExecutionPolicy Bypass -File .\t30-os-auth-matrix.ps1 …`.
4. Каталог платформы — `bin` нужной версии, например
   `C:\Program Files\1cv8\8.3.27.2214\bin`. Дальше он обозначен `$bin`:

   ```powershell
   $bin = "C:\Program Files\1cv8\8.3.27.2214\bin"
   ```

## Ход

Каждый запуск: скрипт выставляет `WA` в секции `[Тест ОС]`, запускает 1С и задаёт три вопроса.

- **Появился диалог входа** — посмотрите, какое имя в нём уже стоит, и войдите как `tester`
  с паролем `1`.
- **Под кем вошли** — в клиенте: меню → «Справка» → «О программе», строка «Пользователь».
  Отвечайте **именем пользователя 1С** (`osuser` или `tester`), не учётной записью Windows:
  файл результатов попадёт в репозиторий.
- Затем закройте 1С и нажмите Enter — скрипт проверит, не переписала ли платформа `ibases.v8i`.

**Шаг 1 — контроль. Без него остальное не имеет смысла.**

```powershell
.\t30-os-auth-matrix.ps1 -BinDir $bin -IbName "Тест ОС" -Run A1
```

Ожидается: вход как `osuser` **без диалога**. Если диалог появился — вход по ОС не настроен,
**дальше не идите**, поправьте пользователя `osuser` и повторите A1. (В T-05.15 первый
контрольный запуск пришлось выбросить ровно по этой причине.)

**Шаг 2 — остальные запуски, по порядку:**

```powershell
.\t30-os-auth-matrix.ps1 -BinDir $bin -IbName "Тест ОС" -Run A0
.\t30-os-auth-matrix.ps1 -BinDir $bin -IbName "Тест ОС" -Run AX
.\t30-os-auth-matrix.ps1 -BinDir $bin -IbName "Тест ОС" -Run B1
.\t30-os-auth-matrix.ps1 -BinDir $bin -IbName "Тест ОС" -Run B0
.\t30-os-auth-matrix.ps1 -BinDir $bin -IbName "Тест ОС" -Run C1
.\t30-os-auth-matrix.ps1 -BinDir $bin -IbName "Тест ОС" -Run D0
.\t30-os-auth-matrix.ps1 -BinDir $bin -IbName "Тест ОС" -Run D1
```

| Запуск | `WA` в файле | Ключи | Режим | Зачем |
| --- | --- | --- | --- | --- |
| A1 | `WA=1` | — | Предприятие | контроль: вход по ОС работает |
| A0 | `WA=0` | — | Предприятие | работает ли `WA=0` |
| AX | нет ключа | — | Предприятие | **главная гипотеза T-30**: так сейчас пишет снятый флажок |
| B1 | `WA=1` | `/WA-` | Предприятие | **T-32**: даёт ли `/WA-` диалог при настроенном входе по ОС |
| B0 | `WA=0` | `/WA+` | Предприятие | перекрывает ли ключ файл в обратную сторону |
| C1 | `WA=1` | `/WA- /N"tester"` | Предприятие | подставится ли имя в диалог без пароля |
| D0 | `WA=1` | — | Конфигуратор | контроль для D1 |
| D1 | `WA=1` | `/WA-` | Конфигуратор | то же, что B1, для конфигуратора |

**Шаг 3 — сохранённый вход (если есть).** Если в диалоге входа есть флажок, запоминающий
вход, — повторите B1, при входе отметьте его, затем ещё раз B1 с заметкой:

```powershell
.\t30-os-auth-matrix.ps1 -BinDir $bin -IbName "Тест ОС" -Run B1 -Note "повтор после сохранённого входа"
```

Так станет видно, пропускает ли платформа диалог при сохранённом входе. Если такого флажка
нет — так и запишите в «Заметки».

**Шаг 4 — штатный стартер.** Откройте его, выберите `Тест ОС` → «Изменить» и пройдите
страницы мастера до параметров аутентификации. Снимите скриншот этой страницы. Для каждого
варианта: выберите его, нажмите «Готово», закройте стартер и выполните

```powershell
.\t30-os-auth-matrix.ps1 -IbName "Тест ОС" -ShowWa
```

Запишите в «Заметки» пары «название варианта → что показал `-ShowWa`».

**Шаг 5 — вернуть всё как было.**

```powershell
.\t30-os-auth-matrix.ps1 -Restore
```

`ibases.v8i` вернётся к копии, снятой перед первым запуском. Всё, что менялось в списке баз
между первым запуском и `-Restore`, при этом откатится — включая добавление `Тест ОС`, если
базу добавляли уже после первого запуска скрипта.

## Что прислать

`t30-results.md` целиком и скриншот страницы аутентификации штатного стартера.
Версию платформы скрипт берёт из пути `$bin` и пишет в каждую строку.
