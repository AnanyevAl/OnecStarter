**Находка по устройству workspace (меняет §14.2).** Импорт **не копирует** проект в
workspace: `E:\edt\тест_2026\` содержит только `.metadata`, проект зарегистрирован в
`.metadata\.plugins\org.eclipse.core.resources\.projects\dev_tools\.location` как
`URI//file:/E:/tmp/edt-test/dev_tools` [Ф]. В рабочих workspace заказчика та же картина:
у `intertop_mp`, `amadeo_kaspi`, `intertop_kaspi`, `(2025) intertop_ka_ws`,
`(2025) amadeo ka for mp` в каталоге workspace **нет ни одного** подкаталога с `.project`,

у остальных внутри лежат только вспомогательные («Серверы», клоны git), а конфигурации —
снаружи [Ф, 11 workspace]. Значит правило §14.2 «подкаталоги workspace с `.project`» даёт
для большинства workspace заказчика пустой или неполный чек-лист «Проверить проекты…».
Формат `.location` (исходники `org.eclipse.core.internal.resources.LocalMetaArea`,
**[Д]**): чанк `SafeChunkyOutputStream` — 16 байт `BEGIN_CHUNK`
(`40 B1 8B 81 23 BC 00 14 1A 25 96 E7 A3 93 BE 1E`), затем `DataOutputStream.writeUTF`
(2 байта длины big-endian + modified UTF-8) строки `URI//<uri>` (пустая строка — проект
в `<workspace>\<имя>`), затем `int` числа динамических ссылок и их имена, затем
`END_CHUNK`. Снятые байты совпадают с форматом [Ф]. Уточнение финального ревью плана 3
по исходникам Eclipse [Д]: перед записью файл очищается (`Workspace.clear`) — в здоровом
файле один чанк; `rfind(BEGIN_CHUNK)` — устойчивость к оборванной записи (BEGIN без END,
затем полный чанк), как `SafeChunkyInputStream.refineChunk`. UNC Eclipse пишет как
`file:////srv/share` (`URIUtil.toURI`, лишняя пара слэшей), authority-форму `file://srv/share`
читает, не пишет [Д]. Скрытые записи (`.org.eclipse.egit.core.cmp`) начинаются с точки.
Решение — в Task 3 плана 3: перечень проектов брать из `.projects\*` с разбором
`.location`, а не из подкаталогов workspace.

**Как устроен `1cedtcli.exe` (снято с дочернего процесса) [Ф].** Это обёртка: пишет
`%TEMP%\1cedt.ini` и `%TEMP%\1cedtcli-startup.txt` (скрипт Gogo: `equinox:start

Наши `-vmargs` сохраняются, но обёртка **дописывает свой `-Dfile.encoding=<кодовая
страница консоли>` после них** — поэтому `-Dsun.stdout.encoding=UTF-8` и парные ему
бесполезны, а вывод команды (таблица `help --status-codes` — тоже cp866, 1235 байт).

даёт у ребёнка `-Dfile.encoding=UTF-8` и вывод в UTF-8 (2060 байт, читается без ошибок)
[Ф]. Значит кодировку журнала чинит смена кодовой страницы скрытой консоли до запуска,
а не флаги JVM → правка `build_cli_command`/`spawn` в Task 3.
