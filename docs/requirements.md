# Требования

> Статус: заполнено по итогам сессии сбора требований 30.07.2026.
> Детальный дизайн v1 — [superpowers/specs/2026-07-30-v1-core-design.md](superpowers/specs/2026-07-30-v1-core-design.md).

## 1. Задача

**OneCStarter** — открытое рабочее место специалиста 1С под Windows. Ядро — запуск
информационных баз с полным контролем версии платформы; вокруг ядра поэтапно вырастают
инструменты: запуск серверов, проекты EDT, конструктор параметров командной строки,
технологический журнал, публикации веб-серверов.

**Аудитория:** разработчики и администраторы 1С — люди с 20–50 базами, несколькими
версиями платформы, серверами и EDT. Сегмент «конечный пользователь с тремя базами»
сознательно не целевой: ему хватает штатного стартера.

**Распространение:** публичный open source на GitHub под лицензией MIT (выбрана
при публикации 16.08.2026). Монетизации нет. Телеметрии нет.

**Конкуренты:** штатный `1cestart.exe` (есть у всех, но примитивен) и StartManager 1.4
(функционален, но закрыт, не развивается и не поддерживает новые версии платформы).

## 2. Чем оно лучше штатного `1cestart.exe`

| # | Что не так в штатном стартере | Как решаем | Как измерим |
| --- | --- | --- | --- |
| А | Версия платформы неуправляема: стартер сам решает, чем запускать; несоответствие видно только после падения | Колонка версии (с разрядностью) у каждой базы, подсветка не установленных на машине версий, явный выбор версии запуска | Выбор версии — чистая функция с табличными тестами; в UI версия видна до запуска |
| Б | Плоский список не масштабируется: нет поиска, избранного, истории | Дерево групп, фильтрация по набору текста, избранное, история запусков, трей и глобальный хоткей | Запуск любой из 50+ баз — не более 5 нажатий клавиш, без мыши |
| Г | Добавление базы — ручное заполнение полей | Drag&drop каталога файловой базы в окно, автозаполнение полей | Добавление файловой базы — одно перетаскивание + Enter |
| Д | StartManager умер вместе с новыми версиями платформы; штатный стартер знает только «свои» версии | Знание о версиях платформы — данные, не код | Выход новой 8.3.x/8.5.x не требует релиза приложения для запуска баз |
| Е | Управление локальными серверами разработки требует ручных скриптов и ручной перерегистрации COM: штатного «запустить сервер нужной версии» нет вовсе | v2: раздел «Серверы» — именованные профили с запуском/остановкой и статусом по факту; смена версии MMC-консоли одним действием ([спека](superpowers/specs/2026-08-26-v2-servers-design.md)) | Запуск сервера нужной версии — два клика без консоли; смена версии консоли — одно действие + UAC |
| Ж | Параметры запуска набираются вслепую: ключей командной строки у платформы десятки, справка по ним — вне программы, а стартер держит их одной строкой в свойствах базы (`AdditionalParameters`, **[Д]**) без подсказок и проверки; опечатка видна только после запуска | v4: конструктор параметров — каталог ключей с описаниями и группировкой по смыслу, строка собирается из выбранного | Ключ ставится выбором из каталога, а не набором по памяти; собранная строка видна до запуска |
| З | Битая ссылка не видна: штатный стартер показывает запись с несуществующим каталогом наравне с живой, отказ виден только после запуска | v2.4: метка в списке — крестик на значке размещения и суффикс «(нет каталога)» в метке строки; проверка каталога и файла базы в фоне при старте и по `F5` | База с удалённым каталогом отличима в списке без наведения мыши и без запуска |
| — | Доверие: пользователь боится сломать свой список баз | `ibases.v8i` — источник правды; после любой нашей операции файл полностью рабочий для штатного стартера | Roundtrip-тесты чтения/записи; удаление OneCStarter ничего не теряет |

## 3. Сценарии использования

По убыванию частоты:

1. Запустить одну из многих баз с клавиатуры: хоткей или трей → 2–3 буквы → Enter.
2. Запустить базу конкретным клиентом: тонкий, толстый, конфигуратор; веб-базу — тонким
   клиентом либо в браузере, по выбору в записи или по настройке ([Ф] T-05.16:
   штатный стартер веб-базу с `App=ThinClient` и с `App=Auto` открывает тонким
   клиентом по `/IBName` — замеры № 1 и № 8, браузер при этом не открывается;
   браузер он открывает **только** при `App=WebClient` — замер № 11, клиент 1С
   при этом не запускается вовсе).
3. Понять до запуска, какой версией запустится база и установлена ли эта версия.
4. Добавить файловую базу перетаскиванием каталога; серверную и веб — через диалог.
5. Навести порядок в списке: группы, порядок, избранное.
6. Очистить кэш базы.
7. Создать ярлык Windows на базу.
8. Посмотреть базы из общих списков (`CommonInfoBases`), не редактируя их.

## 4. Границы

**Не делаем никогда:** 1С:Предприятие 7.7; Snegopat; VCL-стили и подобная косметика
StartManager; обновление конфигураций (`.cf`, каталоги обновлений, downloads.1c.ru);
телеметрия и любой сбор данных.

**Не в v1:** бэкапы как подсистема — выгрузка `.dt` закрывается конструктором параметров
в v4; проверка и ремонт БД (`chdbfl`); редактирование общих списков; автообновление
приложения и проверка релизов на GitHub. Хранение логина и пароля — v2.2.

Правка 23.08.2026 (решение заказчика): проверка релизов на GitHub не входит в 1.0 —
первый кандидат в v1.1. Это новая функциональность, ей нужен полный цикл
(brainstorming → спека → план); смешивать её с выпуском релиза нельзя. Если делать —
только по явному действию пользователя, без фоновых запросов: обещание «без телеметрии
и любого сбора данных» из «не делаем никогда» — часть доверия к программе.

**Бренд:** визуальный стиль — по мотивам портала «1С для разработчиков» (тёмная тема,
боковая навигация), но без логотипа 1С, фирменных знаков и названий, вводящих
в заблуждение о происхождении продукта.

**Платформа:** только Windows в v1.

## 7. Уже принятые решения

| Решение | Обоснование |
| --- | --- |
| GUI на PySide6 | Единственный вариант с работоспособным деревом, drag-n-drop и треем |
| `ibases.v8i` — источник правды | Совместимость со штатным стартером, точка отката для пользователя |
| Только Windows в v1 | Покрывает подавляющее большинство пользователей 1С |
| Python ≥ 3.13 | Ограничений со стороны PySide6 нет |
| Публичный open source, без монетизации | Защита Python-байткода иллюзорна; открытость — главный аргумент доверия для админской аудитории |
| Аудитория — специалисты, не конечные пользователи | 80% функций — инструменты специалиста; за «бухгалтера» со штатным стартером конкурировать бессмысленно |
| Форма — рабочее место с боковой навигацией | v2–v5 добавляются разделами без перелома UI; в v1 панель свёрнута до одного раздела |
| Свои данные (история, избранное, настройки) — в `%APPDATA%\OneCStarter\`, не в `.v8i` | Неизвестно, сохраняет ли штатный стартер чужие ключи (T-02.5); рисковать списком пользователя нельзя |
| Версии платформы — декларативный реестр данных | Боль Д: новая версия не должна требовать релиза |
| Без телеметрии | Аргумент доверия для open source-инструмента админской аудитории |
| Ключ привязки наших данных — `ID` записи, при его отсутствии суррогат из имени и строки соединения | Закрыт T-02.5 и реализован в v2.2; `ID` есть не у всех записей, ограничения суррогата — спека v2.2, §8 |
| Сборка — PyInstaller, не Nuitka | Решено по факту: one-dir + smoke собранного экземпляра, ложных срабатываний антивирусов на сборках 0.1.0–2.3.0 не было |
| Лицензия MIT | Выбрана при публикации репозитория 16.08.2026, файл `LICENSE` в корне |
