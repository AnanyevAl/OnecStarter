# Хранение логина и пароля для запуска базы — дизайн v2.2

Решения заказчика 04.09.2026, три раздела утверждены в брейншторминге.
Базовая точка — `master@6af3605` (v2.1.0 выпущена, слита и запушена, 1829
тестов зелёные). Версия поднимается до `2.2.0` в конце вехи.

Механизм, выбранный заказчиком: учётные данные хранятся в Windows Credential
Manager (DPAPI) и **передаются в командной строке** клиента 1С через `/N` и `/P`.
Это разворачивает решение v1 «секреты в аргументы не попадают» — осознанно,
с записанной ценой (§2) и с экспериментом до кода (§1).

## §0. Предпосылки — факты, а не память

| Факт | Достоверность | Следствие |
| --- | --- | --- |

## §1. Шаг 0 — эксперимент T-05.14, гейт вехи

**До записи [Ф] в скил `platform-launch` код в `domain/` и `services/` по
этой вехе не пишется.** Тот же протокол, что спека 4b §6.3 планировала
и отложила за отсутствием базы.

**Тестовая база — заводит заказчик** (запуск 1С и Конфигуратора — только его
действие):

1. Штатный стартер → «Добавить» → «Создание новой информационной базы» →
   **без конфигурации**, каталог вроде `D:\1C\test-auth`, имя `Тест пароля`.
2. Конфигуратор → Администрирование → Пользователи → Добавить: имя `tester`,
   одноразовый пароль, «Аутентификация 1С:Предприятия» **включена**,
   «Аутентификация операционной системы» **выключена**.
3. Готовность: запуск из штатного стартера **спрашивает** логин и пароль.

**Матрица запусков** — из PowerShell, по образцу строки, которую строит
программа (`ENTERPRISE /IBName"…" /AppAutoCheckVersion /AppAutoCheckMode`);
`/N` и `/P` ставятся сразу после `/IBName`:

| # | Добавка | Что отвечает |
| --- | --- | --- |
| A | ничего | контроль: диалог обязан появиться |
| B | `/N"tester" /P"<пароль>"`; если спрашивает — повтор без кавычек `/Ntester /P<пароль>` | **главный вопрос** — перекрывают ли ключи запись из `.v8i`; заодно форма значения |
| C | рабочая форма из B + `/WA-` | нужен ли `/WA-` рядом |
| D | `/IBConnectionString"File=…"` + рабочая форма из B вместо `/IBName` | запасной путь |

**Снимается на каждый запуск:** появился ли диалог; под кем вошли (заголовок
окна или «О программе»); SHA-256 `ibases.v8i` до и после — **не дописала ли
платформа пароль в файл сама** (если дописала, DPAPI бессмысленно и веха
останавливается); снимок `Get-CimInstance Win32_Process -Filter "Name='1cv8.exe'
OR Name='1cv8c.exe'" | Select CommandLine` — документальное подтверждение
утечки.

**Исходы** записываются в скил `platform-launch` как **[Ф]** с датой;
опровергнутое исправляется:

- B работает → строим на `/IBName /N /P`, без `/WA-`;
- B спрашивает, C работает → `/WA-` обязателен рядом с учётными данными;
- работает только D → базы с сохранённым паролем запускаются строкой
  соединения; теряются диагностика неуникального имени ([Ф] T-05.3) и чтение
  `WA`/`DefaultVersion` из секции — компромисс фиксируется в спеке отдельно;
- ничего не работает → **веха останавливается**, [Ф] записан, через argv не строим.

Запуски делает заказчик; скрипт-помощник (печатает команду, считает хеши,
снимает командную строку процесса) пишет исполнитель задачи 0 плана. В записи
эксперимента пароль заменяется на `<пароль>` — в репозиторий не идёт даже
одноразовый.

**Не измеряется в этой вехе (решение заказчика 04.09.2026):** поведение
базы с `WA=1`, у которой сохранён пароль. Остаётся **[Р]**, см. §8.

## §2. Модель угроз — что защищено, что нет

| Угроза | Открытый текст в `.v8i` (штатный стартер) | DPAPI + argv (этот дизайн) |
| --- | --- | --- |
| Другой пользователь той же машины читает файл | утечка | защищено — DPAPI привязан к учётной записи |
| Файл ушёл в бэкап, синхронизацию, на общий диск | утечка навсегда | защищено — секрета в файлах нет |
| Вредоносный код под **вашей** учётной записью | утечка (файл) | утечка (расшифрует DPAPI или прочтёт argv) |
| Любой процесс под вашей учётной записью **во время работы клиента** | утечка (файл) | **утечка (argv)** — неустранимо |

Честная формулировка для пользователя, она же — текст предупреждения в диалоге:
*«Хранится в диспетчере учётных данных Windows. При запуске передаётся
в командной строке и виден любой программе, работающей под вашей учётной
записью, всё время работы клиента»*. Показывается **постоянно** рядом
с галочкой, не одноразовым окном: одноразовое закрывают не читая.

## §3. Хранение

**Логин — не секрет.** Живёт в `bases.json` полем `login: str | None`
в `BaseUserData`, рядом с избранным и историей. Кодек читает через `.get`,
схема остаётся `1`: старые версии программы поле игнорируют, новая читает
старые файлы. `set_login()` — по образцу `set_favorite()`.

**Пароль — только Credential Manager.** Через `keyring`: сервис `OneCStarter`,
имя записи — ключ привязки базы (`id:<GUID>` либо суррогат `cs:<хеш>|<имя>`,
`services/model.py::binding_key`). **[Д]** ограничения Credential Manager:
блоб до 2560 байт, имя цели до 32767 символов — запас многократный.

**Куда пароль не попадает никогда:** `.v8i` (гарантия v1 сохраняется —
диалог по-прежнему не создаёт способа записать его туда), `bases.json`,
сообщения об ошибках, логи, `LaunchOutcome`, `repr` любых объектов (§5).

**Жизнь ключа:**

- запись без `ID` получает его при первой правке, ключ меняется с `cs:` на
  `id:` — секрет переезжает **в том же блоке** `Workspace._write(rekey_from=…)`,
  где `rekey()` переезжают наши данные; `keyring` переименования не умеет —
  читается, пишется под новым именем, удаляется старое;
- `remove_infobase` удаляет секрет; отказ удаления — сообщение об осиротевшем
  секрете, молчать нельзя;
- снятие «Запомнить пароль» — удаление секрета.

## §4. Ввод — оба диалога (решение заказчика 04.09.2026)

Три строки формы сразу после «Клиента» — в обоих диалогах одинаково
(в диалоге свойств за ними идёт «Аутентификация ОС», в диалоге добавления
её нет, и это ничего не меняет):

| Строка | Виджет | Умолчание |
| --- | --- | --- |
| Пользователь | `QLineEdit` | логин из `bases.json`, если есть |
| Пароль | `QLineEdit`, `EchoMode.Password` | **пусто**; если пароль сохранён — подсказка «сохранён», ввод заменяет |
| Запомнить пароль | `QCheckBox` + постоянная подпись из §2 | **выключено** |

**Сохранённый пароль в диалог не возвращается** — ни в поле, ни в `repr`,
ни через аксессор. Диалог знает только признак `has_password`.

**Отдельный путь записи.** Учётные данные не идут через `changes()`,
`update_infobase`, `new_record()` и `NewInfobase`: `.v8i`-патч по построению
не имеет к ним доступа. У диалога отдельный аксессор
`credentials() -> DialogCredentials(login, password | None, remember)`,
`password` с `repr=False`. Записывает их отдельная операция
`Workspace.set_credentials(key, login, password, remember)`.

**Диалог добавления.** `add_infobase` возвращает ключ новой записи; сразу
за ним — `set_credentials(key, …)`. Отказ второго шага **не откатывает**
первый: база уже в файле, и текст сообщения обязан это различать —
«база добавлена, пароль не сохранён», а не «не удалось добавить».

**Логин без пароля** допустим: один `/N`, платформа спросит только пароль.
Пароль без логина смысла не имеет — «ОК» неактивна с пояснением, тем же
приёмом, что у обязательных полей (отказ до действия). Из того же следует:
**очистка поля «Пользователь» при сохранённом пароле удаляет и пароль** —
секрет без логина неприменим, а оставлять его в хранилище молча нельзя;
диалог говорит об этом подписью до нажатия «ОК».

## §5. Запуск

`Workspace.launch(key)` → логин из `_user[key].login`, пароль из
`store.read(key)` → `Credentials(login, password)` → `launch_infobase(…,
credentials=)` → `build_arguments(…, credentials=)` → `/N… /P…` сразу
после `/IBName`, в форме, подтверждённой запуском B (§1) → `spawn`.

- `Credentials` — frozen dataclass в `domain/launch.py`, `password` объявлен
  `field(repr=False)`: дефолтный `repr` датакласса печатал бы пароль в любой
  трассировке и в `pytest -rA`.
- `/WA-` добавляется **только если** так скажет запуск C эксперимента (§1).
- Страж секретов в строке соединения (`/IBConnectionString`) не меняется:
  учётные данные приходят отдельным аргументом, а не внутри `connect`.
- `record_launch` пишет в `bases.json` то же, что сейчас: клиент и время.
- Ярлык `.lnk` несёт только `--ib-name` нашей программы ([Ф] `shortcut_command`),
  учётные данные в него не попадают; запуск по `--ib-name` идёт через тот же
  `Workspace.launch` и получает их тем же путём.

## §6. Редакция командной строки

Сегодня текст ошибки запуска и `LaunchOutcome.command_line` несут командную
строку целиком с пометкой «секретов в ней нет: запуск идёт по /IBName».
С `/P` это перестаёт быть правдой. `security/secrets.py` получает
`redact_arguments(arguments: str) -> str`: значение `/P…` → `/P***`;
fail-closed на непарной кавычке — вся строка заменяется заглушкой, как
в `redact_connect`. Все показы командной строки идут через неё: текст
`LaunchError`, `LaunchOutcome.command_line`. Серверный журнал
(`services/servers.py`) не трогается: команды `ragent` строятся другим путём
и учётных данных баз не несут — применять редакцию там значило бы править
файл ради правила без предмета.

## §8. Отказы и ограничения

- Хранилище недоступно при записи → `CredentialStoreError`; `.v8i` уже
  записан — сообщение говорит это явно.
- Хранилище недоступно при запуске → запуск **без** учётных данных, платформа
  спросит сама; сообщение — после запуска, как у `UserDataWriteError`:
  процесс уже порождён, и это не отказ запуска.
- Удаление записи, секрет не удалился → запись удалена, сообщение об
  осиротевшем секрете.
- **Принято как ограничение [Р]:** пароль, сохранённый у базы с `WA=1`.
  Диалог не запрещает; поведение не измерено (заказчик отказался от второй
  тестовой базы). Условие пересмотра: появление такой базы у заказчика.
- **Принято как ограничение [Д]:** утечка через argv на время сеанса.
  Устранить нельзя, только ограничить хранение и предупредить — что и сделано.

## §9. Упаковка — keyring-гейт

`keyring` ищет бэкенды через entry points; в замороженной сборке PyInstaller
без `hiddenimports=["keyring.backends.Windows"]` он **молча** уходит в пустой
бэкенд и все операции отказывают. Поэтому **задача 1 плана — smoke на
собранном экземпляре**: `set_password`/`get_password`/`delete_password`
под служебным именем `OneCStarter-smoke`, после — проверка, что записи нет.
`build/smoke.py` подменяет `APPDATA`, но Credential Manager к `APPDATA` не
привязан — поэтому служебное имя и обязательное удаление.

Если round-trip в frozen-сборке не проходит и причина не в `hiddenimports` —
откат на обёртку `advapi32` через `ctypes` по образцу `platform_1c/job.py`
(«один `WinDLL` на модуль»), `keyring` из зависимостей убирается. Решение
принимается **в задаче 1, по замеру**, а не заранее.

## §10. Инварианты

1. **Qt только в `ui/`.** `security/credentials.py` импортирует `keyring`,
   тот Qt не тянет; модуль добавляется в `CORE` стража.
2. **Выбор версии — чистая функция.** Не затрагивается.
3. **Форматы 1С без потерь.** `.v8i` этой вехой не меняется вовсе.
4. **Атомарная запись.** `bases.json` — прежним `atomic_write`.
5. **Секреты — только через `security/`.** Хранилище, редакция и определение
   секрета — там; `domain` и `services` держат пароль только в `Credentials`
   с `repr=False` и не логируют его ни в одной ветке.

## §11. Тесты

Защитные (обязательна мутация; что ломали — в `docs/tasks.md`):

| Тест | Мутация, на которой обязан упасть |
| --- | --- |
| `Credentials` не печатает пароль в `repr`/`str` | снять `repr=False` |
| `set_credentials` не пишет пароль ни в `bases.json`, ни в `.v8i` — **по файлам с диска** | положить пароль в `BaseUserData` |
| Текст `LaunchError` не несёт `/P…` | убрать `redact_arguments` из сообщения |
| `LaunchOutcome.command_line` редактирован | то же для исхода |
| `remove_infobase` удаляет секрет | убрать вызов `delete` |
| Rekey переносит секрет на новый ключ | убрать перенос из `_write` |
| Снятие «Запомнить» удаляет секрет | не удалять при `remember=False` |
| Диалог не показывает сохранённый пароль | подставить его в поле |
| «Запомнить пароль» выключено по умолчанию | включить |
| Оба пути применения зовут `set_credentials` **по клику ОК** | отвязать сигнал |
| Отказ хранилища при добавлении — база добавлена, текст различает | слить в одну ошибку |

Табличные без мутации: `redact_arguments` (в том числе непарная кавычка →
заглушка); `build_arguments` с учётными данными — побайтово, включая кавычку
и пробел в пароле; кодек `login` туда и обратно; `credentials_of`.

Smoke: keyring round-trip в frozen-сборке (§9).

**Живая проверка заказчиком** перед сдачей — урок v2.1: тесты проверяют
состояние, а не вид. Показать собранный экземпляр: диалог с тремя строками,
предупреждение, запуск тестовой базы без запроса пароля.

## §14. Отклонённые альтернативы

| Вариант | Почему нет |
| --- | --- |
| Открытый текст в `.v8i`, как штатный стартер | Единственный путь, точно работающий с `/IBName` без замера, — но утечка в покое навсегда: бэкапы, синхронизация, соседи по машине. Проект отказался в v1 явно; заказчик 04.09.2026 подтвердил отказ |
| Не строить хранение в v2.2 | Заказчик выбрал строить, приняв утечку argv как условие |
