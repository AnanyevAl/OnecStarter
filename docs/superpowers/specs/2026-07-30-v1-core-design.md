# Дизайн v1 — ядро запуска информационных баз

> Утверждён заказчиком 30.07.2026 в сессии brainstorming.
> Контекст и критерии успеха — [../../requirements.md](../../requirements.md).
> Факты о 1С здесь не дублируются: формат `.v8i` — скил `v8i-format`, механика запуска —
> скил `platform-launch`. Утверждения с пометкой **[не проверено]** требуют эксперимента
> (см. T-02 в [../../tasks.md](../../tasks.md)) до реализации соответствующего кода.

## 1. Форма продукта

Одно окно. Слева — узкая панель навигации по разделам; в v1 раздел один — «Базы»,
панель свёрнута и почти незаметна. Каркас рассчитан на разделы v2–v4 (Серверы,
Параметры запуска, ТЖ, Публикации, EDT): каждый раздел — независимый модуль
со своим виджетом.

Визуальный стиль — тёмная тема по мотивам портала «1С для разработчиков»
(`temp/style/`): плоские списки, боковая навигация, жёлтый акцент. Без бренда 1С.

Приложение сворачивается в трей; глобальный хоткей поднимает окно с фокусом
в строке поиска. Из меню трея запускается избранное.

## 2. Раздел «Базы»

### Дерево

- Источник — `ibases.v8i`: группы-папки формата, порядок и сортировка — как в файле.
- Виртуальные узлы поверх файла: **Избранное** и **Недавние** (история запусков).
  Живут в наших данных (§3, «Наши данные»), в `.v8i` не пишутся.
- Отдельная ветка — базы из общих списков (`1cestart.cfg` → `CommonInfoBases`),
  только чтение, редактирование заблокировано и объяснено в UI.
- Колонки: имя; версия платформы с разрядностью; дата последнего запуска.
  Версия, не установленная на машине, подсвечивается как проблема — до запуска.

### Поиск и запуск с клавиатуры

Набор текста в окне фильтрует дерево. Целевой сценарий: хоткей → 2–3 буквы → Enter,
итого ≤5 нажатий до запуска любой из 50+ баз.

Enter запускает базу в её режиме по умолчанию. Отдельные действия (кнопки, контекстное
меню, хоткеи): тонкий клиент, толстый клиент, конфигуратор; для веб-баз — браузер.
**[не проверено]** выбор исполняемого файла тонкого клиента для файловой базы —
T-02.6, до кода запуска.

### Операции

- **Добавление:** drag&drop каталога файловой базы в окно (автозаполнение имени
  и строки соединения) или диалог с тремя размещениями: файловая / серверная / веб.
- **Редактирование свойств**, перемещение по группам drag&drop, изменение порядка.
- **Удаление из списка** — файлы базы не трогаются, UI говорит это явно.
- **Ярлык Windows** на базу (.lnk, запуск через OneCStarter или напрямую — решим в плане).
- **Очистка кэша** базы: локальный кэш; состав и расположение серверного реестра
  кэшей — **[не проверено]**, уточнить экспериментом до реализации.

## 3. Архитектура

Пакеты и их обязанности (инварианты из `CLAUDE.md` действуют):

| Пакет | Обязанность | Qt | Побочные эффекты |
| --- | --- | --- | --- |
| `domain` | Модель списка баз; выбор версии платформы (чистая функция, всё окружение аргументами); построение командной строки | нет | нет |
| `config` | Чтение/запись `.v8i` и `1cestart.cfg` без потерь; атомарная запись | нет | ФС |
| `platform_1c` | Обнаружение установленных версий; запуск процессов | нет | ФС, реестр, процессы |
| `security` | Секреты. В v1 почти пуст (пароли не храним), граница держится с первого дня | нет | — |
| `services` | Сценарии: добавить базу, запустить, очистить кэш, следить за файлом | нет | через `config`/`platform_1c` |
| `ui` | PySide6: каркас разделов, раздел «Базы», трей | да | — |

### Версии — данные, не код (боль Д)

Всё специфичное для версий платформы — имена исполняемых файлов, расположение,
особенности ключей — в декларативном реестре (файл данных в поставке). Новая версия
с теми же соглашениями работает без изменений; изменение соглашений — правка данных.
Реестр обновляем отдельно от релизов кода.

### Сосуществование со штатным стартером

`ibases.v8i` может быть изменён извне в любой момент:

- watcher на файл + перечитывание при внешних изменениях;
- перед записью — проверка, не изменился ли файл с момента чтения; при конфликте
  перечитать и повторить операцию поверх свежего состояния, не затирая чужое;
- запись всегда атомарная: временный файл в том же каталоге + замена.
- **[не проверено]** держит ли `1cestart.exe` файл заблокированным — T-02.4.

### Наши данные

`%APPDATA%\OneCStarter\`: история запусков, избранное, настройки окна и приложения.
В `ibases.v8i` свои ключи не пишем: неизвестно, переживут ли они перезапись штатным
стартером (T-02.5). Привязка к базе — по ключу `ID` записи, если он есть, иначе
по строке соединения; точная стратегия — в плане, после T-02.5.

### Секреты

Пароли в командную строку не попадают никогда. В v1 хранения паролей нет вообще —
используется то, что уже есть в `.v8i` (`Usr=`), и аутентификация ОС.

## 4. Отказоустойчивость

- Битые записи `.v8i` не валят приложение: база показывается с пометкой
  «не разобрано», при записи её байты возвращаются как были.
- Ошибка запуска — сообщение с фактической командной строкой (без секретов)
  и действием «скопировать для отчёта».
- Отсутствующая версия платформы видна до запуска; предлагается выбрать другую.

## 5. Тестирование

- Табличные тесты выбора версии платформы (чистая функция).
- Roundtrip-тесты `.v8i` на обезличенных фикстурах: прочитать → записать →
  байтовая эквивалентность (с поправкой на намеренно изменённое). Включая
  экзотические кодировки и неизвестные ключи.
- Тесты атомарности и конфликтной записи.
- UI — минимальный smoke: создание окна, модель дерева. Без процессов 1С.
- Процессы 1С в тестах не запускаются никогда.
- `mypy --strict` (кроме `ui`), `ruff`, `pytest` — в CI на GitHub Actions.

## 6. Поставка

- Сборка в exe: PyInstaller или Nuitka — решим в плане (вес, ложные срабатывания
  антивирусов).
- Установщик Inno Setup + переносимый zip.
- Автообновления нет; ненавязчивая проверка новых релизов на GitHub.
- Телеметрии нет.
