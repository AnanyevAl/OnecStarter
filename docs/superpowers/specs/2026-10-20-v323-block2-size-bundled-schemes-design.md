## 2. T-24.1–24.2 — схемы в поставке

### 2.1. Набор

Исходник — каталог `editor-themes/` репозитория на коммите
`e1f4094c166b12957d4497e76c50dc57fb5f013b` (04.10.2026): 362 файла `.xml`, 43,6 МБ,
около 120 КБ на тему (**[Ф]** GitHub API 20.10.2026).

В репозиторий кладутся **не XML, а `.csi`**, полученные нашим разборщиком:
`parse_idea_xml` → `complete` → `to_csi`. Диалог из любой темы берёт только 22 цвета
палитры редактора, и ровно этот путь проходит XML, открытый пользователем из своего
каталога, — результат тот же. Проба 20.10.2026 (**[Ф]**): `base16-3024.xml` 120 469 байт →
22 цвета из 22 → `.csi` 1522 байта; весь набор — порядка 550 КБ вместо 44 МБ.
MIT разрешает переработку при сохранении уведомления — `LICENSE` лежит рядом.

Темы, давшие 0 цветов или ошибку разбора, в набор не попадают (правило выпуска: в поставке
только то, что наш разборщик понимает).

### 2.2. Где лежит и как попадает в сборку

- `src/onecstarter/schemes/base16/*.csi`, `LICENSE` (копия файла репозитория base16),
  `SOURCE.md` (репозиторий, коммит, дата, способ конвертации, число тем и отброшенных).
- Путь во время работы — `services/edt_scheme.py::bundled_schemes_dir()`:
  `importlib.resources.files("onecstarter") / "schemes"` (образец — `registry.toml`
  в `platform_1c/registry.py`). В сборке — `_internal/onecstarter/schemes`.
- `build/onecstarter.spec`: каталог добавляется в `datas` явно, по образцу `registry.toml`.
- При обновлении установщик пересоздаёт `_internal` (T-21) — набор обновляется вместе
  с версией. Так и нужно: каталог поставки только для чтения.

### 2.3. Получение набора

`build/vendor_base16.py` — запускается вручную, разово и при смене коммита; результат
коммитится. Сборке сеть не нужна. Скрипт: список файлов `editor-themes/` на заданном коммите
через GitHub API, загрузка каждого с `raw.githubusercontent.com`, конвертация, запись в
каталог набора (старое содержимое `*.csi` удаляется), копия `LICENSE`, `SOURCE.md`.
Только стандартная библиотека и наш пакет.

### 2.4. Диалог «Цветовая схема…»

- `SchemeDialog` получает второй каталог — параметр `bundled: SchemeCatalog | None = None`.
  Раздел EDT передаёт `SchemeCatalog(str(bundled_schemes_dir()))`.
- Список источников: «Текущая», «По умолчанию EDT», затем записи **обоих** каталогов одним
  списком, по алфавиту (правило `entries()`); путь к файлу — в подсказке строки.
- Подсказка `HINT_NO_DIR` («Каталог схем не задан») показывается, только если нет ни своего
  каталога, ни схем поставки. `HINT_MISSING_DIR` — как сейчас, если свой каталог задан, но
  не найден; схемы поставки при этом в списке остаются.
- Загрузка записи от каталога не зависит — `SchemeCatalog.load` выносится в функцию модуля
  `load_entry(entry)`, метод остаётся тонкой обёрткой.
- «Сохранить в файл…» — в свой каталог, если он есть, иначе в «Документы» (как сейчас).
  **В каталог поставки — никогда**: он перезаписывается при обновлении.

## 3. T-33 — колонка «Размер»

### 3.1. Откуда размер

Проба доступности (v2.4, `services/availability.py::_probe_one`) уже вызывает
`stat(<каталог>\1Cv8.1CD)` для каждой абсолютной файловой записи — в фоне, с поколениями,
по F5. Размер берётся из этого же вызова (`st_size`): **новых обращений к диску и сети нет**.

- `_probe_one` возвращает `(Availability, int | None)`; размер — только у `PRESENT`.
- `probe_paths(targets, stat, report, report_size=None)` — необязательный второй обратный
  вызов. Существующий `report(key, state)` и его тесты не меняются.
- `ui/background.py::AvailabilityProbe` — новый сигнал `sized = Signal(str, object)`
  (ключ пути, размер или `None`) с той же защитой по поколениям, что у `probed`.
- `BasesView.apply_size(key, size)` копит размеры по ключу пути и перестраивает список тем же
  таймером, что и `apply_availability`. Проводка — в `ui/app.py`, рядом с `probed`.

### 3.2. Колонка

- `ui/bases/tree_model.py::COLUMNS` — четвёртая колонка «Размер», последней (номера прежних
  колонок не меняются). `build_model(..., sizes=None)` — отображение «ключ записи → байты»;
  перевод «ключ пути → ключ записи» делает вьюха, как для доступности.
- Текст — `services/display.py::format_size`: до 1024 байт — «N Б», дальше КБ, МБ, ГБ, ТБ
  с одним знаком после запятой («1,2 ГБ»), двоичные единицы; округление не даёт «1024,0 КБ».
  Подсказка ячейки — точное число: «1 234 567 байт».
- Выравнивание текста — по правому краю.
- Пусто: группы, серверные и веб-базы, база до первого ответа пробы, `MISSING`,
  относительный путь.

## 4. Тесты

- `format_size` — табличный тест (0, 1023, 1024, граница округления, ГБ, ТБ, запятая).
- `probe_paths` с `report_size`: размер у доступной базы, `None` при отказе `stat`
  каталога и файла базы; без `report_size` поведение прежнее.
- `AvailabilityProbe.sized`: результат приходит; устаревшее поколение молчит.
- Модель: колонка «Размер» заполнена у записи из `sizes`, пуста у группы и серверной базы.
- Вьюха: `apply_size` + перестройка → текст в колонке.
- Набор поставки: каталог есть, `LICENSE` есть, записей не меньше 300, каждая загружается
  `load_entry` и даёт 22 цвета.
- Диалог: записи обоих каталогов в списке; без своего каталога, но со схемами поставки —
  подсказки нет; «Сохранить» предлагает путь не в каталоге поставки.
- Мутационная проверка: «Сохранить» в каталог поставки → тест обязан упасть.
