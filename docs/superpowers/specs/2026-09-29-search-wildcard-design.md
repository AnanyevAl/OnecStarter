# Поиск со звёздочкой в «Базах» и проектах EDT — дизайн

Дата: 29.09.2026. Пожелание заказчика: в поле поиска набрать `amad*UU` и найти все
строки, где есть `amad` и затем `UU`.

## 1. Постановка

Заказчик назвал это «поиском по регулярному выражению», но пример — шаблон со звёздочкой:
как регулярное выражение `amad*UU` означает «ama, сколько угодно `d`, UU» и строку
«amad Бухгалтерия UU» не находит. Полноценные регулярные выражения отвергнуты: в именах
баз обычны `.`, `(`, `)`, `+` («Бухгалтерия 3.0», «УТ (копия)») — запрос `УТ (` дал бы
ошибку разбора, `3.0` совпал бы с «3x0».

Решено: `*` — «любые символы», всё остальное ищется буквально.

## 2. Правило совпадения

Чистая функция `matches_pattern(text: str, query: str) -> bool` в новом модуле
`src/onecstarter/domain/search.py` (без Qt, инвариант 1).

1. Запрос обрезается по краям (`strip`). Пустой запрос совпадает со всем.
2. Сравнение без учёта регистра: `casefold` и текста, и запроса — как в нынешнем поиске
   (T-05.3: платформа сравнивает имена баз регистронезависимо).
3. Запрос делится по `*` на части, пустые части отбрасываются. Нет ни одной непустой части
   (запрос `*`, `**`) — совпадает со всем.
4. Части ищутся **по порядку**: каждая — `str.find` от конца совпадения предыдущей.
   Совпадения частей не перекрываются: `aa*aa` на «aaa» — нет совпадения, на «aaaa» — есть.
5. Шаблон **не привязан** к началу и концу текста: `amad*UU` совпадает с
   «Копия amad-2 UU test». `*` по краям запроса ничего не меняет.
6. Пробелы внутри частей значимы: `amad * UU` ищет «amad », затем « UU».
7. Других спецсимволов нет: `?`, `.`, `(`, `[`, `\` ищутся буквально. Модуль `re`
   не используется — ни экранирования, ни ошибок разбора.
8. Запрос без `*` ведёт себя в точности как нынешняя проверка подстроки
   (`query.strip().casefold() in text.casefold()`).

Решения заказчика: порядок частей учитывается (вариант «в любом порядке» отклонён);
область — «Базы» и проекты EDT, диалог «Цветовая схема…» не меняется.

## 3. Где подключается

- **«Базы»** — `services/display.py::filter_rows`: условие
  `needle in row.label.casefold()` заменяется на `matches_pattern(row.label, query)`.
  Остальная семантика `filter_rows` не меняется: совпавший узел остаётся со всем
  поддеревом, предок — с отфильтрованными потомками, NOTE-строки не совпадают никогда.
- **Проекты EDT** — `ui/edt/tree_model.py::matches`: шаблон проверяется **отдельно**
  по `project.name` и по `project.workspace`, результат — «или». Текст не склеивается:
  иначе `amad*UU` совпал бы при `amad` в пути и `UU` в имени.
- **Подсказки полей** (`SearchField` дописывает « (Ctrl+F)» сам):
  - `ui/bases/view.py`: «Поиск: имя базы, * — любые символы»;
  - `ui/edt/view.py`: «Поиск: имя проекта, * — любые символы».
  Итог в поле: «Поиск: имя базы, * — любые символы (Ctrl+F)». Ширину поля проверить
  глазами на собранном экземпляре: подсказка не должна обрезаться при ширине окна
  по умолчанию; обрезается — сокращать текст, а не менять вёрстку.

## 4. Тесты

- Табличный тест `matches_pattern` (`tests/domain/test_search.py`): без звёздочки
  (подстрока, регистр, «ё» не приравнивается к «е» — как сейчас); по порядку; обратный
  порядок не совпадает; `*` по краям; одинокая `*` и `**`; пустой и пробельный запрос;
  спецсимволы `. ( ) + [ ? \` буквально; неперекрытие частей (`aa*aa` на «aaa» / «aaaa»);
  значимые пробелы внутри частей; кириллица с разным регистром.
- `filter_rows`: запрос со звёздочкой оставляет совпавшую базу и её группу-предка
  и убирает несовпавшую.
- `matches` EDT: совпадение по имени; совпадение по пути; части, разнесённые между
  именем и путём, **не** совпадают.
- Подсказки: правятся ожидания в `tests/ui/test_bases_view.py` и
  `tests/ui/test_edt_view.py`. `tests/ui/test_search_field.py` проверяет механику
  суффикса и не меняется.
- Мутационная проверка по правилу проекта не требуется: табличные тесты чистой функции.
  Для теста «разнесённые между именем и путём — не совпадают» склеивание всё же проверить
  мутацией (временно искать по `name + workspace`): это поведение нечистой обвязки.
