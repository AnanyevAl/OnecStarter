# 3.2.3, блок 3 — уведомление о новой версии и установка по кнопке — дизайн

Дата: 20.10.2026. Задача: T-25 ([tasks.md](../../tasks.md)). Ветка `feat/2026-10-20-v323`.

## 1. Решения заказчика 20.10.2026

- **Согласие спрашивается один раз.** При первом запуске 3.2.3 с показанным окном — вопрос
  «Проверять обновления при запуске?». Ответ хранится в настройках, меняется в Настройках →
  «О программе». Кнопка «Проверить обновления» там же работает всегда.
- **Найдена новая версия — уведомление и кнопка «Установить».** Автоматической установки без
  щелчка нет (T-25.2 откладывается).
- **Portable и запуск из исходников — только уведомление со ссылкой.**
- **T-24.3 (докачка схем из сети) отложена**: набор base16 в поставке и свой каталог закрывают
  задачу; вернуться, когда появится реальный источник.

Конфликт с §4 требований («только по явному действию пользователя, без фоновых запросов»,
23.08.2026) снимается правкой §4: фоновая проверка допустима только после явного согласия,
запрос не несёт данных о пользователе.

## 2. Проверка

- Адрес: `https://api.github.com/repos/AnanyevAl/OnecStarter/releases/latest`. Репозиторий
  публичный — без токена (лимит GitHub для анонимных запросов — 60 в час на адрес, **[Д]**
  документация GitHub; одна проверка за запуск укладывается с запасом).
- Заголовки: `User-Agent: OneCStarter/<версия>`, `Accept: application/vnd.github+json`.
  Больше ничего: ни идентификаторов, ни данных о машине (инвариант 5 и обещание §4).
- Таймаут 10 с. Прокси — системный: `urllib.request` на Windows читает его из реестра.
  Прокси с NTLM-аутентификацией не поддерживается — проверка завершится ошибкой (**[?]**,
  не проверено на корпоративной сети).
- Фоновая проверка при старте — только при согласии и только когда окно показано (тихий
  старт в трей вопрос не задаёт и не проверяет). Поток-демон, как у пробы доступности.
- Ошибка фоновой проверки (сеть, прокси, лимит, неожиданный ответ) — строка в журнале,
  без окон. Ошибка ручной проверки — текст причины в строке статуса раздела настроек.
- `releases/latest` не отдаёт черновики и предварительные выпуски (**[Д]** документация GitHub).
- Версия — числовое сравнение кортежей из тега (`v3.2.4` → `(3, 2, 4)`); тег, который так
  не разбирается, — «новой версии нет», а не ошибка.

## 3. Уведомление

Полоса над разделами главного окна: «Вышла версия 3.2.4 · [Установить] · [Что нового] · ×».

- «Что нового» — страница релиза (`html_url` ответа) в браузере.
- «Установить» — только у версии, поставленной установщиком: признак — `unins000.exe` рядом
  с исполняемым файлом в собранном экземпляре. Portable и запуск из исходников кнопки не имеют.
- × скрывает полосу до следующего запуска.

## 4. Установка по кнопке

1. Ассет релиза с именем на `-setup.exe`; нет такого — кнопки «Установить» нет.
2. Скачивание в фоне в `%TEMP%\OneCStarter-update\<имя>`; полоса показывает «Скачивание…».
3. Проверка SHA-256 скачанного против `digest` ассета (`sha256:<hex>`, **[Ф]** GitHub API
   20.10.2026 отдаёт его у ассетов 3.2.2). Нет `digest` или не совпал — отказ с объяснением,
   файл удаляется, установщик не запускается.
4. Затем — обычное подтверждение выхода программы (вопросы о работающих серверах и командах
   CLI EDT, если они есть). Отказ — установщик не запускается, скачанный файл остаётся
   до следующей попытки.
5. Подтверждено — запуск установщика обычным открытием файла (оболочка Windows), выход
   программы. Установщик ставится без прав администратора (`PrivilegesRequired=lowest`)
   и в конце предлагает запустить программу (`[Run] postinstall`).

Уточнение к согласованному дизайну (20.10.2026, при записи спеки): «закрыться без вопроса
о выходе» заменено на «пройти обычное подтверждение выхода»: пропускать вопрос о работающих
серверах опасно.

## 5. Устройство

- `domain/update.py` (без Qt, без сети): `version_tuple`, `is_newer`, `Release`,
  `parse_release(payload)`, `sha256_matches(data, digest)`.
- `services/update.py` (без Qt): `fetch_latest(http_get)`, `download_verified(release,
  directory, http_get)`, `is_installed_copy(exe_dir)`, `urllib_get` — HTTP по умолчанию.
  Ошибки — `UpdateError(ServicesError)`, текст без путей пользователя.
- `services/settings.py`: поле `check_updates: bool | None = None` («не спрашивали»).
- `ui/update.py`: `UpdateChecker` и `UpdateDownloader` (QObject, поток-демон, сигналы),
  `UpdateBanner` (полоса), `UpdateController` (согласие, старт, ручная проверка, установка).
- `ui/shell.py`: место для полосы над стеком разделов.
- `ui/settings_view.py`, «О программе»: флажок «Проверять обновления при запуске», кнопка
  «Проверить обновления», строка статуса.
- `ui/app.py`: сборка контроллера в `_build_main_window`, запуск — в `main()` после показа окна.

## 6. Тесты

- Табличные: `version_tuple`, `is_newer`, `parse_release` (с ассетом установщика и без,
  без `digest`, битый ответ), `sha256_matches`.
- Сервис с подменённым HTTP: успешная проверка; ошибка сети → `UpdateError`; скачивание
  с верным `digest` пишет файл; с неверным — `UpdateError`, файла нет.
- `is_installed_copy`: есть `unins000.exe` / нет.
- Настройки: `check_updates` читается и пишется, незнакомое значение — `None`.
- UI: полоса (текст, кнопка «Установить» только у установленной копии, ×);
  контроллер — согласие «Да»/«Нет»/не спрашивали, ручная проверка пишет статус,
  установка зовёт подтверждение выхода и запускает установщик только после него.
- Мутационные проверки: несовпавший SHA-256 обязан блокировать запуск установщика;
  ответ «Нет» не должен приводить к проверке при старте.
