# v3.1 — замечания по проверке v3: дизайн

Решения заказчика 15.09.2026, сессия brainstorming. Базовая точка — `master@95308b7`
(v3.0.0 выпущена 14.09.2026, 2441 тест). Версия вехи — `3.1.0`.

Повод — замечания 1–6 из [tasks.md](../../tasks.md), T-17.4 «Замечания по проверке v3».
Все шесть — интерфейс; форматов 1С/EDT, процессов и файлов заказчика веха не касается,
поэтому раздела фактов с метками достоверности здесь нет: единственный внешний факт —
поведение Qt, и он проверяется тестами.

## §2. Виджет `ui/path_link.py::PathLink`

Один виджет для обеих панелей. `QLabel` с rich-text.

- `set_path(text, *, directory: str | None = None)`:
  `directory` задан — текст рисуется ссылкой `<a href>` цветом `palette.accent`,
  подчёркивание, курсор-рука; `None` — обычный текст цветом `palette.text`. Пустой `text` —
  виджет показывает `placeholder` (серым, `palette.text_dim`), меню без пунктов.
- Длинный путь обрезается многоточием по ширине виджета (`fontMetrics().elidedText`,
  `ElideMiddle`, пересчёт в `resizeEvent`); полный текст — всплывающая подсказка всегда.
- Клик по ссылке (`linkActivated`) → сигнал `open_requested(str)` с каталогом; открытие —
  забота панели (`open_in_explorer`, как сейчас у кнопки). Клавиатура: виджет получает
  фокус по Tab, Enter активирует ссылку (штатно у `QLabel` с `LinksAccessibleByKeyboard`).
- ПКМ → контекстное меню (`CustomContextMenu`): «Открыть каталог» (только когда есть
  `directory`), «Копировать» (когда есть текст). «Копировать» кладёт **полный** текст,
  не обрезанный. Меню ставится на виджет целиком, не только на текст ссылки.
- `apply_palette(palette)` перерисовывает цвета — как у остальных виджетов темы.
- Доступ для тестов: `path_text()` (полный; `QLabel.text()` занят разметкой), `elided_text()`,
  `placeholder()`, `context_menu()` — построить меню без показа, `link_href()`.

## §3. Панели

**EDT** (`ui/edt/panel.py`): строки «Рабочая область» и «Каталог проекта» — `PathLink`
вместо `QLineEdit` + кнопок. Каталог проекта не задан — placeholder «не задан — редакторы
получают рабочую область». Каталога нет на диске — при клике то же сообщение, что сейчас
у «Открыть каталог» (`show_error` панели), ссылка при этом остаётся ссылкой: проверять
диск на каждую перерисовку панели не нужно, файловая доступность (v2.4) EDT не касается.

**Базы** (`ui/bases/panel.py`): `ConnectionPanel` показывает `PanelCard` как сейчас; поле
пути — `PathLink`: `directory` = `ConnectionPath.directory` (заполнен только у файловой
базы), `text` — как сейчас (`File=`, `Srvr/Ref`, URL). `show_actions` из `PanelCard`
больше не нужен — удаляется вместе с кнопками; `hint` показывается placeholder'ом.
Реакция на отсутствующий каталог — прежняя.

## §4. «Рабочая область»

Все строки, видимые пользователю: диалог записи (метка поля, ошибки «Рабочая область не
задана», «Путь рабочей области должен быть абсолютным»), подсказка каталога проекта, панель,
`services/edt.py` (`InvalidRequestError`), `services/edt_cli.py::RUNNING_REASON` («Закройте
EDT: рабочая область занята»), причина отказа при живой команде CLI, тексты кодов CLI в
консоли («рабочая область занята другим приложением», «см. журналы рабочей области»),
подтверждение сборки («Пересобрать все проекты рабочей области «…»?»), placeholder имени
нового проекта в диалоге импорта, подсказки дерева. README и `requirements.md` §5 — тоже.
Спека v3 и протоколы экспериментов не правятся: там «workspace» — термин Eclipse.

## §5. Колонка «Память»

- `domain/edt.py::effective_heap_mb(project_vm_args: str, installation_vm_args: str) -> int | None`:
  `-Xmx` записи, иначе установки, иначе `None`; разбор — `split_vm_args` (последний
  `-Xmx` в строке побеждает, как у JVM). Чистая функция, табличный тест. Настройка
  «память по умолчанию» в цепочку **не** входит: она лишь подставляется в диалог новой
  записи, в командную строку запуска не попадает (уточнение 15.09.2026 при написании плана;
  в brainstorming цепочка была названа с настройками — это было неверно). Если `-Xmx` нет
  ни у записи, ни у установки, JVM возьмёт `-Xmx4096m` из `1cedt.ini` установки ([Ф] спека
  v3 §0) — но ini мы не разбираем, поэтому в колонке «—».
- `ui/edt/tree_model.py`: `COLUMNS = ("Проект", "EDT", "Память")`; ячейка записи —
  `f"{mb} МБ"`, иначе «—» с подсказкой «-Xmx не задан — действует значение из 1cedt.ini
  установки»; выравнивание вправо; у группы пусто. Ширина по умолчанию 90, как у «EDT» —
  110; последняя колонка не растягивается (правило плана 1: `stretchLastSection(False)`).

## §6. Поиск

- Кнопка очистки в полях поиска `ui/bases/view.py` и `ui/edt/view.py` — своё действие
  `QLineEdit.addAction(clear_icon(palette), TrailingPosition)`, а не штатный
  `setClearButtonEnabled`: у штатного значок — из системной темы Qt, и его видимость на
  нашей тёмной палитре ничем не гарантирована; свой значок рисуется цветом `palette.text_dim`
  по образцу `ui/rail_icons.py`. Действие видно только при непустом тексте
  (`textChanged` → `setVisible`), клик — `clear()`, фокус остаётся в поле. Перерисовка
  при смене темы — `apply_palette` вьюхи.
- Подсказки: «Поиск: начните вводить имя базы (Ctrl+F)», «Поиск: начните вводить имя
  проекта (Ctrl+F)».
- `ui/shell.py`: один `QShortcut(QKeySequence.StandardKey.Find, window)`; обработчик берёт
  `current_section()` и, если у него есть метод `focus_search()`, зовёт его. «Серверы»
  метода не имеют — комбинация ничего не делает. `focus_search()` вьюхи: `setFocus()` +
  `selectAll()`.

## §7. «О программе»

`ui/settings_view.py`: группа «О ПРОГРАММЕ» последней. Строки: «Версия» — `3.1.0`
(`importlib.metadata.version("onecstarter")`; нет метаданных — «неизвестна», без
исключения); «Репозиторий» — `QLabel` со ссылкой `https://github.com/AnanyevAl/OnecStarter`,
`setOpenExternalLinks(True)`. Версия в exe: `build/onecstarter.spec` обязан включать
метаданные пакета (`copy_metadata("onecstarter")`), smoke пишет `smoke: version=<x.y.z>`
и гейт `build/smoke.py` требует совпадения с `pyproject.toml`.
